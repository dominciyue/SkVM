# 🌍 i18n-helper — 国际化/本地化助手

## 触发条件
当用户要求以下操作时激活此技能：
- 扫描代码中的硬编码中文/英文文本
- 为项目添加国际化支持（i18n）
- 批量提取和翻译语言文件
- 检查翻译完整性（缺失 key 检测）

## 工作流程

### 1. 项目分析与约束确认
- 先读取用户提供的契约、清单或 schema；其中的框架、扫描范围、允许修改/必须新建/受保护文件、文本确认规则、key 规则和输出 ABI 优先于通用流程
- 将精确字段列表和 `additionalProperties: false` 视为闭集，不自行添加“有用”字段；区分“缺失/不适用”和“检查通过”
- 再检测项目类型、现有 i18n 框架与依赖，并只扫描约定范围；不要为完成任务安装依赖或访问网络，除非用户明确允许
- 修改前记录受保护文件及现有文件集合，以便完成后核对副作用

### 2. 硬编码文本扫描
- 在约定的 `.js/.jsx/.ts/.tsx/.vue/.py/.java/.go` 等文件中搜索；若契约定义了“确认文本”，只提取满足该规则的文本
- 排除变量名、URL、正则表达式、import 路径、技术术语、测试选择器和调试日志等非用户文案
- 优先使用契约或源码中已有的 key；仅在没有 key 规则时提出稳定、语义化的 key，并去重

### 3. 语言文件生成
只生成用户或契约要求的文件，并采用项目框架要求的格式：
- **JSON** (i18next/react-intl): `{ "key": "value" }`
- **YAML** (vue-i18n): `key: value`
- **PO/POT** (gettext): 标准格式
- **Properties** (Java): `key=value`

所有 locale 必须采用同一 key 集；无法可靠翻译的值应按任务规则标记或报告，不得把缺失状态写成“已完成”。

### 4. 代码替换
- 将确认的硬编码文本替换为当前框架的 i18n 调用，不改动未确认文本
- 保持变量标识符和占位符一致：源码表达式、语言文件占位符及调用参数必须一一对应
- 示例：
  ```javascript
  // 替换前
  alert('保存成功');
  // 替换后
  alert(t('alert.saveSuccess'));
  ```

### 5. 完整性与副作用检查
完成写入后、回复用户前：
- 解析生成的 JSON/YAML/PO/Properties，并在本地工具可用且无需安装时执行类型检查或框架检查
- 对比全部 locale 的 key 集，列出每个 locale 的真实缺失 key，并校验占位符集合
- 若有输出 ABI，逐项校验必填字段、类型、枚举、顺序/去重规则和禁止的额外字段
- 核对只修改/创建允许的文件、必须文件均存在、受保护文件未变；无法执行的检查要明确说明，不能声称已验证

## 输出格式
若用户或契约指定输出路径、格式或 ABI，严格按其要求输出，下面的 Markdown 仅作为未指定格式时的默认报告：

```markdown
## 📊 i18n 扫描报告

### 硬编码文本
| 文件 | 行号 | 内容 | 建议 key |
|------|------|------|----------|
| src/App.tsx | 42 | '欢迎使用' | page.welcome |

### 语言文件
已生成 `locales/zh-CN.json` 和 `locales/en-US.json`

### 翻译完整性
- zh-CN: 45/45 (100%) ✅
- en-US: 42/45 (93.3%) ⚠️ 缺少 3 个 key
```

## 支持的 i18n 框架
- react-intl / FormatJS
- vue-i18n
- i18next / react-i18next / next-i18next
- Angular @ngx-translate
- Python gettext / Flask-Babel
- Java ResourceBundle / Spring MessageSource
- Go go-i18n

## 注意事项
- 不要翻译技术术语（API、SDK、HTTP 等）
- 保留变量占位符 `{name}` `{{count}}` `%s` 等格式
- 复数形式和性别变体需要特殊处理
- 日期、数字、货币格式需使用 locale 感知的格式化函数
