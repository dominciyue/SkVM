# 🌍 i18n-helper — 国际化/本地化助手

## 触发条件
当用户要求以下操作时激活此技能：
- 扫描代码中的硬编码中文/英文文本
- 为项目添加国际化支持（i18n）
- 批量提取和翻译语言文件
- 检查翻译完整性（缺失 key 检测）

## 工作流程

### 1. 先分析项目与约束
- 检测项目类型（React/Vue/Angular/Node.js/Python/Java 等），识别已使用的 i18n 框架，并扫描源代码目录结构。
- 如果项目提供契约、配置或输出 schema，先读取它；把允许修改/必须创建/受保护文件、确认条件、精确 key 规则和报告 ABI 当作本次任务的边界。契约声明的字段集合是闭集，不要添加“合理但未声明”的字段。
- 先记录输入文件、现有 locale、依赖和限制；不安装依赖、不联网，除非用户明确允许。

### 2. 按规则扫描并提取
- 在 `.js/.jsx/.ts/.tsx/.vue/.py/.java/.go` 等文件中搜索硬编码字符串，并仅提取规则明确确认的用户可见文本；没有确认依据的文本保留为待人工判断，不要猜测。
- 排除变量名、URL、正则表达式、import 路径、日志调试信息及契约列出的其他排除类别。
- 使用契约指定的原始文件路径和精确 key；去重但保留报告要求的文件顺序。记录插值表达式中的每个标识符。

### 3. 生成语言文件与配置
根据项目框架生成对应格式：
- **JSON** (i18next/react-intl): `{ "key": "value" }`
- **YAML** (vue-i18n): `key: value`
- **PO/POT** (gettext): 标准格式
- **Properties** (Java): `key=value`
- 各 locale 必须覆盖同一组已确认 key；保留并转换插值占位符，翻译内容不得改变占位符标识符。React 使用 i18next 时，初始化资源、locale 名称和 `react-i18next` 接入方式应与项目依赖及契约一致。

### 4. 代码替换
- 将已确认的硬编码文本替换为对应 i18n 函数调用，不扩大修改范围；保留技术术语、调试逻辑、属性语义和组件结构。
- JSX 插值转换为命名占位符，并把相同标识符传给翻译函数；不要把任意表达式静默改写成猜测的变量名。
- 示例：
  ```javascript
  // 替换前
  alert('保存成功');
  // 替换后
  alert(t('alert.saveSuccess'));
  ```

### 5. 完整性检查与交付
- 对比所有 locale 的 key 集合，输出每个 locale 的缺失 key；检查 JSON/配置语法、占位符一致性、引用路径和重复 key。
- 若存在输出 ABI，逐字段核对必填字段、类型、枚举值、额外字段和数组去重/排序要求；报告中的扫描文件和提取 key 必须来自实际扫描结果。
- 最后核对文件清单：只修改允许文件、只创建要求文件、受保护文件未变更。只声称实际执行过的检查；若某项检查因环境或权限未执行，明确说明并保留该风险。
## 输出格式
```markdown
## 📊 i18n 扫描报告

### 硬编码文本
| 文件 | 行号 | 内容 | 建议 key |
|------|------|------|----------|
| src/App.tsx | 42 | '欢迎使用' | page.welcome |

### 语言文件
已生成 `locales/zh-CN.json` 和 `locales/en-US.json`

### 翻译完整性
- zh-CN: 45/45 (100%) ✅
- en-US: 42/45 (93.3%) ⚠️ 缺少 3 个 key
```

## 支持的 i18n 框架
- react-intl / FormatJS
- vue-i18n
- i18next / react-i18next / next-i18next
- Angular @ngx-translate
- Python gettext / Flask-Babel
- Java ResourceBundle / Spring MessageSource
- Go go-i18n

## 注意事项
- 不要翻译技术术语（API、SDK、HTTP 等）
- 保留变量占位符 `{name}` `{{count}}` `%s` 等格式
- 复数形式和性别变体需要特殊处理
- 日期、数字、货币格式需使用 locale 感知的格式化函数
