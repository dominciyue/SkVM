# 🌍 i18n-helper — 国际化/本地化助手

## 触发条件
当用户要求以下操作时激活此技能：
- 扫描代码中的硬编码中文/英文文本
- 为项目添加国际化支持（i18n）
- 批量提取和翻译语言文件
- 检查翻译完整性（缺失 key 检测）

## 工作流程

### 1. 先读取项目契约，再分析项目
- 优先读取用户提供的契约、schema 或 output ABI；其中声明的文件范围、确认规则、键规则、字段集合和额外属性约束是权威的闭合集合，不要自行添加“合理”的字段或文件。
- 记录允许修改的文件、必须创建的文件、受保护文件、目标框架和输出路径；只在这些范围内操作。
- 检测项目类型、现有 i18n 框架及源代码目录。没有契约时，才使用通用约定，并向用户说明仍需由其确认的假设。

### 2. 按确认规则扫描并参数化
- 在 `.js/.jsx/.ts/.tsx/.vue/.py/.java/.go` 等文件中搜索候选字符串，但只提取契约明确确认的用户可见文本；例如，契约要求带指定标记时，未带标记的文本不能擅自提取。
- 排除变量名、URL、正则表达式、import 路径、日志调试信息、技术术语和测试选择器，除非契约明确将其纳入。
- 对每个确认项保留源文件、位置、原文、精确键和插值标识符。若契约指定键值，必须原样同时用于 locale 文件和调用参数，不要改名或重新分组。

### 3. 生成语言文件
根据项目框架生成对应格式，并为每个确认键建立完整的语言集合：
- **JSON** (i18next/react-intl): `{ "key": "value" }`
- **YAML** (vue-i18n): `key: value`
- **PO/POT** (gettext): 标准格式
- **Properties** (Java): `key=value`
- JSX 表达式应转换为命名插值占位符，并将相同标识符传给 i18n 调用；不要丢失、改名或把表达式值误当作静态文本。
- 翻译不确定时保留原文或标记待翻译，不凭空改变业务含义；复数、性别、日期、数字和货币遵循目标框架的 locale 感知机制。

### 4. 代码替换
- 仅替换已确认的文本，并使用目标框架的正确 hook、函数或组件；保持 JSX/模板结构、变量语义和非目标代码不变。
- 逐项核对“源码确认键 = 调用参数 = 各 locale 的键”。不要为了看起来完整而替换未确认文本。

### 5. 完整性检查与交付边界
- 比较每个 locale 的扁平化键集合与确认键集合，分别输出缺失键；若 ABI 指定缺失键按 locale 分组，必须保留每个声明的 locale（包括空数组），并严格遵守字段顺序/去重/额外属性约束。
- 检查 JSON/YAML/PO 等格式可解析、键无重复、插值标识符在源码与 locale 间一致、目标调用可对应现有初始化方式。
- 用项目已有且无需安装依赖的检查命令或轻量解析方式验证；禁止为验证安装包、联网或生成契约未允许的临时/辅助文件。
- 最后重新枚举工作区变更：确认允许修改和必需创建的文件均满足，受保护文件和其他文件均未变化；报告只写入契约声明的路径。无法运行编译或检查时如实说明原因，不把“未执行”写成“通过”。

## 输出格式
- react-intl / FormatJS
- vue-i18n
- i18next / react-i18next / next-i18next
- Angular @ngx-translate
- Python gettext / Flask-Babel
- Java ResourceBundle / Spring MessageSource
- Go go-i18n

## 注意事项
- 不要翻译技术术语（API、SDK、HTTP 等），除非项目契约明确要求。
- 保留变量占位符 `{name}`、`{{count}}`、`%s` 等格式；对 JSX 表达式优先使用目标框架规定的命名插值。
- 复数形式和性别变体需要特殊处理。
- 日期、数字、货币格式需使用 locale 感知的格式化函数。
- 契约的精确字段列表、允许路径和额外属性规则优先于本技能示例；“不适用”应保持为不适用，不要改写成成功或缺失。
