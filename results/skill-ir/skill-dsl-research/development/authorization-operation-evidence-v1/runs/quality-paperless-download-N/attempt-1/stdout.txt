The Download operation authorizes access against the **root document of the requested document family**, not separately against the version row whose file is ultimately returned.

### No `version` query parameter

- **Root `pk`:** `_get_effective_file_doc` resolves the newest descendant by `version_index`, falling back to the root if there is no descendant.

This means:


```text
GET /api/documents/<version>/download/
```

returns that specific version’s file. Both authorize the root.

### A `version` query parameter is present

Any presence of `version`, including an empty or malformed value, takes the explicit-version path [src/documents/views.py:1375-1385].

Resolution works as follows:

- no truthy value ultimately selects the latest version;
- a non-integer value produces an invalid-version error;
- a nonexistent ID produces not found;
- an existing candidate is accepted only if it is:
  - the root itself, or

An unrelated document/version is rejected as not found [src/documents/versioning.py:169-195].

Because `_resolve_file_doc` sets `include_deleted=True` whenever the `version` parameter is present, an explicitly selected candidate is looked up through `Document.global_objects`, including soft-deleted versions [src/documents/views.py:1375-1385; src/documents/versioning.py:136-137, 169-195].

The important authorization relationship is:

```text
requested pk

```

Version selection is family-constrained, so it cannot name an arbitrary unrelated document. It nevertheless changes the file-producing row without causing a new authorization check on that selected row.
