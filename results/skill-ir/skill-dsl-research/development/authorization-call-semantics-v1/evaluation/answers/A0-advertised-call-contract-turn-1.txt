## 1. Requested document, version, and returned file

1. The default router registers `UnifiedSearchViewSet` under `documents`; that class inherits `DocumentViewSet`. The `download` GET detail action calls `file_response(..., "attachment")`.  
   `src/paperless/urls.py:74-77`, `src/documents/views.py:2503`, `src/documents/views.py:1834-1839`

2. `pk` is looked up with `Document.global_objects`, because `file_response` calls `_resolve_request_and_root_doc(..., include_deleted=True)`. Thus the initial lookup may find deleted documents or versions. Missing `pk` raises `Http404`.  
   `src/documents/views.py:1401-1415`, `src/documents/views.py:1429-1436`

3. Root resolution:
   - If the requested row is already a root, it is the root.
   - If it is a version, its related root is used.
   - If that root cannot be loaded, the helper falls back to the requested row.  
   `src/documents/versioning.py:146-156`

4. After root authorization, the effective file document is selected:
   - **PK names a version and no `version` query parameter:** return that exact requested version.
   - **No `version` parameter:** choose the newest non-deleted child version, falling back to the root.
   - **Empty `version=` parameter:** parameter presence enables the include-deleted manager, but its empty value is falsy, so the newest version including deleted versions is chosen.
   - **Truthy numeric `version`:** load that ID, including deleted rows, and accept it only if it is the root or a child of that root.
   - **Non-integer version:** DRF `NotFound`.
   - **Missing or unrelated version ID:** `Http404`.  
   `src/documents/views.py:1375-1399`, `src/documents/versioning.py:136-142`, `src/documents/versioning.py:159-195`

5. Representation selection occurs after document/version selection:
   - Original is forced only when `original` is present with the exact string `"true"`.
   - Otherwise archive is used when the selected document has an archive version.
   - Otherwise source/original is used.  
   `src/documents/views.py:1368-1373`, `src/documents/views.py:1442-1448`

6. `serve_file` opens `archive_file` with PDF MIME type for archive mode, or `source_file` with the document MIME type for original mode. Download always uses attachment disposition. File absence is converted to 404 by `download`.  
   `src/documents/views.py:1834-1839`, `src/documents/views.py:4941-4995`

For the supplied development fixture—not deployment fact—the default request selects root `10`, newest visible version `11`, and `v1-archive.pdf`.

## 2. Authorization checks and ordering

The order is:

1. DRF performs authentication, global permission checks, and throttling before invoking the action.  
   `framework/rest_framework-3.18.1/rest_framework/views.py:404-421`, `framework/rest_framework-3.18.1/rest_framework/views.py:507-524`

2. `DocumentViewSet` configures `IsAuthenticated` and `PaperlessObjectPermissions`. For GET, the latter maps to the model permission `documents.view_document`; inherited DRF behavior calls `request.user.has_perms(...)`.  
   `src/documents/views.py:1008-1022`, `src/documents/permissions.py:30-44`, `framework/rest_framework-3.18.1/rest_framework/permissions.py:233-246`

3. Inside `file_response`, the requested row and root are resolved.

4. The explicit action check evaluates `view_document` against the **resolved root**:
   - The `ObjectPermissionChecker` is constructed first.
   - An unowned root passes.
   - A root owned by the requesting user passes.
   - A root owned by somebody else requires Guardian `has_perm("view_document", root)`.
   - Failure returns `HttpResponseForbidden` before version or representation selection.  
   `src/documents/permissions.py:624-635`, `src/documents/views.py:1417-1427`

5. Only after that check does the code choose the effective version and original/archive file. It does not call `get_object()` or `check_object_permissions()` for the selected version and performs no second owner-aware check.  
   `src/documents/views.py:1429-1448`

Although `PaperlessObjectPermissions` defines an object-level owner/grant method, this download path does not invoke it for `file_doc`.  
`src/documents/permissions.py:46-53`

## 3. Does alternate version or representation change the authorized resource?

No.

- When `pk` names a version, authorization is still evaluated against its resolved root.
- An explicit `version` may select the root or a related child, but only after root authorization.
- The selected version may have a different owner; that owner is not re-evaluated by this action.
- Choosing original versus archive only changes the handle, MIME/filename behavior, and returned bytes. It does not change the authorization target.

Therefore the action-specific authorized resource is the root document, while versions and original/archive files are post-authorization representations.
