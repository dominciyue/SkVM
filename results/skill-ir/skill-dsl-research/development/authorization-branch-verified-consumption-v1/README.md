# BM: branch completion and directed consumption

This directory owns only the current development experiment. Production runs use the ordinary inquiry adapter; no study-specific evaluator is exposed to the model. `manifest.json` fixes purpose, budget, selection and evaluation rules before inference. The 18 scenarios are previously exposed development cases, not held-out evidence.

From the repository root, use `bun run results/skill-ir/skill-dsl-research/development/authorization-branch-verified-consumption-v1/study.ts <command>`:

- `prepare` writes deterministic finite inputs and initializes an absent ledger.
- `preflight` verifies the public tools, source boundary and prior terminal dispositions with zero inference.
- `run A0 first` repairs the exact BL raw; `freeze first` pins that completed A0 before consumers. A1 starts empty and cannot replace it.
- `run <purpose> <attempt>` records every initial/repair attempt. Existing identities cannot be resent. Repairs require named evidence in `repairs.json` and stay within the registered four-purpose allowance.
- `offline` (also `evaluate` or `replay`) runs the fixed raw on the finite development matrix, then verifies portable archives and invalidation on a separate changed-source copy. `offline <repo-relative-program> <track>` evaluates another raw separately.
- `sharelink` checks the existing developer-assisted second structure offline, writing only in this directory.
- `status`, `summarize`, and `verify` inspect recorded progress, aggregate observed usage, and verify archives.

Evaluation field mappings are reviewed against exact raw hashes in `assessment.ts`; absent mappings stay pending. Natural quality is evaluated independently after delivery against the original four questions, supplied finite assumptions and source citations. Source meaning, conditional precision, current values, omitted duties and delivery are separate axes. A claim that supplied facts were absent fails condition precision even if a generic deployment caveat is otherwise reasonable. Full natural quality requires all four duties, accurate current scenario and no material unsupported assertion. Token input includes cached input once; USD and human time remain unknown. A negative first pair requires a concrete documented implementation intervention before the second pair; otherwise it is recorded not-run-no-intervention.

Local run/session archives and copied sources are retained but ignored. Reviewed raw programs, metrics, finite matrices and dispositions are published. `finiteQueueComplete` never implies `researchGoalAchieved`.
