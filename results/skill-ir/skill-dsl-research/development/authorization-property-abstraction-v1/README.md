# AZ property abstraction development

This directory owns the AZ0–AZ18 development records. Requirements are not observed outcomes. Historical AY/AX files are read-only sources; original answers and scores remain unchanged.

The explicit `operation-evidence-v6` core binds task properties to current source evidence, retains unknown influences, records bounded summary adoption and reports local checks separately from whole-task coverage. Full dynamic framework composition is still incomplete.

From the checkout root:

```powershell
bun ./results/skill-ir/skill-dsl-research/development/authorization-property-abstraction-v1/study.ts dry-run single-download
bun ./results/skill-ir/skill-dsl-research/development/authorization-property-abstraction-v1/study.ts prepare single-download
bun ./results/skill-ir/skill-dsl-research/development/authorization-property-abstraction-v1/study.ts run single-download
```

All experiments use the existing official `gpt-5.6-sol/high` account boundary. The runner records exclusive attempt identities and refuses active/unknown runs or a currently refused/unavailable channel. A named revision preserves its original attempt. It never switches accounts or retries automatically.

The fixed denominator is 12 quality positions through the same native entrance, plus one development property, two original-byte consumers and six changes. `quality-*-D-repeat-1` also represents the corresponding full original skill use. Other positions are selected by their registered manifest ID. Changes require `prepare-changes current` after a current original consumer session; complete reuse benefits additionally require independent full-quality evidence.

The ordinary public command uses the same core:

```powershell
bun ./src/cli.ts authorization inquiry check --input=./results/skill-ir/skill-dsl-research/development/authorization-property-abstraction-v1/model/inputs/download-single.json --method=M --strategy=operation-evidence-v6
```

Account input totals already include cached input. USD, hidden provider requests, development/scout use and human time remain unknown when unreported. Offline tests and replay are engineering evidence, never fresh task quality or account usage.
