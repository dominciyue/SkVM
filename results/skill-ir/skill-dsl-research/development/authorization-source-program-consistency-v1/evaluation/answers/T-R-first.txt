## 1. Requested document and returned file

### Entry and initial document

The API router registers `UnifiedSearchViewSet` under `documents`, and the API router is mounted under `^api/`. `UnifiedSearchViewSet` inherits `DocumentViewSet`. `download` is a GET detail action, giving the logical router path:

```text
/api/documents/{pk}/download/
```

Any deployment-level prefix remains unknown.

Sources:

- `src/paperless/urls.py:74-77,97-100,297`
- `src/documents/views.py:1834-1839,2503`

`pk` identifies the initial `request_doc`. Download calls `_resolve_request_and_root_doc(..., include_deleted=True)`, so lookup uses `Document.global_objects`; a deleted document may therefore be named directly. A missing `pk` raises `Http404`.

Source: `src/documents/views.py:1401-1415,1429-1434`.

### Root resolution

The authorization root is resolved as follows:

1. If `request_doc.root_document_id` is null, `request_doc` is the root.
2. Otherwise, if the related `request_doc.root_document` is loaded and non-null, that object is the root.
3. Otherwise, the global manager looks up `root_document_id`.
4. If that lookup fails, source explicitly falls back to `request_doc` itself.

Source: `src/documents/versioning.py:146-156`.

### Version selection

Version selection occurs only after root authorization succeeds.

| Request condition | Effective `file_doc` |
|---|---|
| `pk` names a version and `version` is absent/null | That exact `request_doc`, even if deleted |
| Root requested; `version` absent/null | Newest visible related version |
| `version=""` | Newest related version including deleted rows |
| Truthy integer `version` | That ID, if it is the root or belongs directly to that root |
| Truthy non-integer `version` | `NotFound("Invalid version parameter")` |
| Numeric ID missing or unrelated to the root | `Http404` |
| No matching latest version | The root itself |

“Newest” means:

```text
version_index DESC NULLS LAST, then id DESC
```

The distinction between absent/null and empty string is caused by two different tests:

- Presence is `version_param is not None`; therefore `""` enables the global/include-deleted manager.
- Resolution uses `if not version_param`; therefore `""` selects the latest-version branch instead of integer conversion.

Sources:

- `src/documents/views.py:1375-1399`
- `src/documents/versioning.py:23-28,136-195`

### Original versus archive

After `file_doc` is selected:

```text
use_archive =
    original query value is not exactly "true"
    AND file_doc.has_archive_version is truthy
```

Consequently:

- Exact `original=true` selects `file_doc.source_file`.
- Any other value, including absence, null, empty string, or `"false"`, selects `file_doc.archive_file` when an archive exists.
- If no archive exists, `source_file` is used.

Source: `src/documents/views.py:1368-1373,1442-1448`.

### Response construction

`serve_file` returns:

- Archive: `archive_file`, MIME type `application/pdf`.
- Original: `source_file`, MIME type from `file_doc.mime_type`.
- Original text/plain or CSV types receive `charset=utf-8`.
- CSV-to-`text/plain` conversion applies only to inline responses, not this attachment download.
- `follow_formatting` changes the response filename, not the selected document or file handle.
- Download passes disposition `attachment`.
- `FileNotFoundError` and `Document.DoesNotExist` escaping `file_response` are converted to `Http404`.

Sources: `src/documents/views.py:1834-1839,4941-4995`.

## 2. Authorization checks and selection order

### Framework checks

Before dispatch reaches `download`, DRF performs:

1. authentication;
2. global permission checks;
3. throttling.

`DocumentViewSet` configures:

```text
IsAuthenticated
PaperlessObjectPermissions
```

For GET, `PaperlessObjectPermissions` maps the model permission to:

```text
documents.view_document
```

The global check is a request/view/model-level check. The source path for Download does not retrieve the selected version through DRF `get_object()` and does not call `check_object_permissions()` on it.

Sources:

- `src/documents/views.py:1008-1022`
- `src/documents/permissions.py:30-44`
- `framework/rest_framework-3.18.1/rest_framework/views.py:331-342,404-421`
- `framework/rest_framework-3.18.1/rest_framework/permissions.py:203-246`

### Action-specific object check

After `request_doc` and `root_doc` are resolved, the action evaluates:

```python
has_perms_owner_aware(request.user, "view_document", root_doc)
```

The helper constructs `ObjectPermissionChecker(user)` first, then allows when:

1. `root_doc.owner is None`; or
2. `root_doc.owner == user`; or
3. Guardian reports `view_document` on `root_doc`.

If none applies, the action returns:

```text
403 "Insufficient permissions"
```

Because checker construction precedes the Python `or` expression, even an owner or unowned-root path requires the constructor to return normally. Guardian `has_perm` itself is called only when the root is owned by someone else.

Sources:

- `src/documents/views.py:1401-1427`
- `src/documents/permissions.py:624-635`

The local helper is skipped when `request.user is None`. Under ordinary DRF dispatch, the configured `IsAuthenticated` check is intended to stop such a request earlier; the finite program cannot prove the runtime authentication outcome.

### Exact order

The relevant order is:

```text
DRF authentication/global permissions
→ request_doc lookup
→ root_doc resolution
→ owner/Guardian authorization on root_doc
→ effective version/file_doc selection
→ original/archive selection
→ FileResponse construction
```

A failed root check returns before version or representation selection. After selection, there is no second owner-aware check and no inherited DRF object-permission invocation for `file_doc`.

Source: `src/documents/views.py:1421-1448`.

## 3. Does an alternate version change the authorized resource?

Normally, **no**.

Authorization remains attached to the resolved `root_doc`. Selecting another version changes `file_doc`, and selecting original versus archive changes the file handle within that `file_doc`; neither operation replaces the authorization target.

The selected version can have a different owner from the root. The source does not re-evaluate that selected row’s owner and does not ask Guardian for permission on the selected row.

Explicit selection is nevertheless constrained to:

- the authorized root itself; or
- a row whose `root_document_id` equals the authorized root’s ID.

An unrelated numeric version therefore returns 404 instead of being served.

There are two important qualifications:

1. If `pk` directly names a version and no `version` parameter is supplied, that exact version is returned, while authorization still targets its resolved root.
2. If the referenced root cannot be resolved and `get_root_document` falls back to the requested version, that requested version becomes `root_doc` and is then the authorization target.

Choosing original versus archive never changes the authorization resource. It only selects `source_file` or `archive_file` after version selection and authorization.

Sources:

- `src/documents/views.py:1388-1448`
- `src/documents/versioning.py:146-195`
