- scenario%3Afile-owner-without-destination-write-grant::entry%3Apost-process-file: source_supported_failure — source_supported_failure. At the declared POST /process/file entry, authentication binds a verified user, and the non-admin branch authorizes access only to the supplied source file by looking it up with both file_id and user.id. The caller-supplied collection_name is then copied into the destination binding and passed to save_docs_to_vector_db with add=True whenever a collection name was supplied. For an existing collection, add=True bypasses the helper's non-add early return, and the protected effect is VECTOR_DB_CLIENT.insert into that named collection. No destination ownership or explicit write-grant check is visible on this path. The separately supplied collection-access validator could raise 403 for denied collections, but the declared process_file path does not invoke it. Thus source-file ownership is treated as sufficient to reach a write to the independently selected destination, contrary to the accepted destination-write policy. The write path requires BYPASS_EMBEDDING_AND_RETRIEVAL to be false and ordinary processing to succeed; that deployment/runtime state is not established by the fixed source, but it is not a missing authorization binding and does not change the source-visible absence of target-specific authorization.
