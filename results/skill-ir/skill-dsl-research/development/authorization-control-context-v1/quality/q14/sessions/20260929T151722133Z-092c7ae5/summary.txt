Before selecting or serving any file version, _resolve_request_and_root_doc applies has_perms_owner_aware(request.user, "view_document", root_doc). That owner-aware check succeeds only when the root is unowned, the caller owns the root, or the object permission checker grants the permission on the root. Under the stated task premises, another user owns the root and the caller has no object view_document grant on it, so the check fails and an HttpResponseForbidden is returned. Ownership of request_doc (the requested version) does not authorize access because the decisive check is against root_doc. The protected effect is therefore blocked before _get_effective_file_doc and serve_file. The supplied global permission and existence facts are accepted scenario premises rather than source/deployment proof.
