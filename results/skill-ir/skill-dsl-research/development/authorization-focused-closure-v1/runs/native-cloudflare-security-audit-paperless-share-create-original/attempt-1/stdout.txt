## Conclusion

Creating a share is subject to two distinct layers:

1. **Endpoint/model-level control:** the caller must be authenticated and pass the POST permission for creating a `ShareLink`, namely `add_sharelink`.
2. **Submitted-document control:** the serializer resolves the submitted `document` and checks that exact `Document` before creating the share.

Therefore, **knowing a valid document ID or possessing only `add_sharelink` is not sufficient**.

The exact-document check, however, is owner-aware:

- an ownerless document passes;
- a document owned by the caller passes; or
- otherwise, `ObjectPermissionChecker` must report `view_document` for that exact document.

Because an **ownerless document passes without an exact-object permission lookup**, the implementation appears to violate the supplied strict policy for that branch: global `documents.view_document`, together with the endpoint’s `add_sharelink`, can be sufficient.

### 4. Exact-document serializer check

`ShareLinkSerializer.validate_document(document)` receives the resolved document object associated with the submitted `document` field. Before returning that object into validated data, it requires all of the following:

```python
self.user is not None
self.user.has_perm("documents.view_document")

```

If any condition fails, it raises `PermissionDenied("Insufficient permissions.")`.

This means:

- mere existence of the document is not authorization;
- knowing its ID is not authorization;
- `add_sharelink` alone is not authorization;
- global `documents.view_document` alone does not normally suffice for an owned document belonging to somebody else;
- the relation/object check is applied to the **exact resolved document**, not merely to the `Document` model generally.

Source: `src/documents/serialisers.py:2873-2886`.

### 5. Owner-aware branches

`has_perms_owner_aware()` is:

```python

return obj.owner is None or obj.owner == user or checker.has_perm(perms, obj)
```

Consequently, document validation succeeds when the caller has global `documents.view_document` and any one of these is true:

1. `document.owner is None`;
2. `document.owner == request.user`; or
3. `ObjectPermissionChecker(request.user).has_perm("view_document", document)` succeeds for that exact document.

The first two branches short-circuit without consulting `ObjectPermissionChecker`.

Source: `src/documents/permissions.py:624-635`.

> A caller creating a document share must have `view_document` permission for the exact shared document. A global `add_sharelink` permission or knowing a document ID alone is insufficient.
