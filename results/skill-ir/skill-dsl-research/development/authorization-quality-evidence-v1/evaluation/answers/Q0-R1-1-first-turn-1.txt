## Scope and conclusion

This is a source-only trace for revision `126ec414a8b65158368653a2604ae58415e43103`. No request was executed, and the supplied fixture is not deployment evidence.

**Core result:** Download authorizes the resolved **root document first**, then selects a document version and its original/archive file. It does **not** repeat object authorization for the selected version or file representation.

## 1. Requested document and returned file

### Entry and initial lookup

- The router registers `UnifiedSearchViewSet` under `documents`; that viewset inherits `DocumentViewSet` (`src/paperless/urls.py:74-77`, `src/documents/views.py:2503-2507`).
- `download` is a GET detail action and calls `file_response(pk, request, "attachment")` (`src/documents/views.py:1834-1839`).
- `file_response` resolves `pk` with `include_deleted=True`, therefore selecting through `Document.global_objects`. A missing row produces 404 (`src/documents/views.py:1401-1415`, `1429-1434`).
- Root resolution is:
  1. if the requested row has no `root_document_id`, it is its own root;
  2. otherwise use the loaded `root_document`;
  3. otherwise query that root ID through the chosen manager;
  4. if no root is found, fall back to the requested row  
  (`src/documents/versioning.py:146-156`).

### Version-selection branches

After root authorization, `_get_effective_file_doc` selects the document whose file is served (`src/documents/views.py:1388-1399`, `1437-1445`):

| Condition | Selected document |
|---|---|
| `pk` names a version and `version` parameter is absent | That exact requested version |
| `version` absent otherwise | Newest related row from `Document.objects`, falling back to root |
| `version=` present but empty | Empty is falsey for parsing but its presence sets `include_deleted=True`; newest related row from `Document.global_objects`, falling back to root |
| Non-empty numeric `version` | That ID, but only if it is the root itself or a direct version whose `root_document_id` equals the authorized root ID |
| Non-empty non-integer `version` | DRF `NotFound("Invalid version parameter")` |
| Numeric version missing or unrelated | 404 |

“Newest” is ordered by `version_index DESC NULLS LAST`, then `id DESC` (`src/documents/versioning.py:23-28`, `159-195`).

The source visibly selects `Document.objects` versus `Document.global_objects`; the precise soft-delete filtering implementation of those inherited managers is not present in the allowed evidence.

### Original/archive selection

After the effective document is selected:

- Archive is used only when:
  - `original` is not exactly the string `"true"`, and
  - `file_doc.has_archive_version` is truthy.
- Otherwise the original is used (`src/documents/views.py:1368-1373`, `1442-1447`).

`serve_file` then chooses:

| Representation | File handle | Content type |
|---|---|---|
| Archive | `file_doc.archive_file` | `application/pdf` |
| Original | `file_doc.source_file` | `file_doc.mime_type`, with UTF-8 charset added for specified text/CSV types |

Because Download uses `attachment`, the inline-only CSV-to-`text/plain` conversion does not apply. `follow_formatting` changes the response filename choice, not the selected document or file handle. The response receives an attachment `Content-Disposition` with normalized and UTF-8 encoded filenames (`src/documents/views.py:4941-4995`).

Synchronous `FileNotFoundError` and `Document.DoesNotExist` escaping `file_response` are converted to 404 by `download` (`src/documents/views.py:1835-1839`).

## 2. Authorization checks and their order

The effective order is:

1. **DRF pre-action processing.** Authentication, global permissions, and throttling run before the action handler (`framework/.../views.py:404-421`).
2. **Authentication requirement.** `DocumentViewSet` configures `IsAuthenticated`, which requires a truthy authenticated user (`src/documents/views.py:1008-1022`; `framework/.../permissions.py:145-151`).
3. **Global model permission.** `PaperlessObjectPermissions` maps GET to `documents.view_document`; inherited `has_permission` calls `request.user.has_perms(...)` (`src/documents/permissions.py:30-44`; `framework/.../permissions.py:233-246`).
4. **Requested-row lookup.** `pk` is fetched before the action-specific root check. Missing rows produce 404.
5. **Root authorization.** `has_perms_owner_aware(user, "view_document", root_doc)` is evaluated:
   - unowned root: allowed;
   - root owned by the user: allowed;
   - root owned by another user: Guardian `checker.has_perm("view_document", root_doc)` decides;
   - false result: 403  
   (`src/documents/permissions.py:624-635`; `src/documents/views.py:1417-1427`).
6. **Version selection.**
7. **Original/archive selection and response construction.**

A notable implementation detail is that `ObjectPermissionChecker(user)` is constructed before the owner/unowned short-circuit expression. Thus even an owner path requires constructor completion, although `has_perm` is called only for another user's root.

The action does not call `get_object()` or `check_object_permissions()` for `request_doc` or `file_doc`. Consequently, `PaperlessObjectPermissions.has_object_permission` is not invoked for the selected version. The only action-specific object check shown here is the explicit root check.

## 3. Does an alternate version or representation change the authorized resource?

**No.**

- If `pk` names a version, authorization is still evaluated on its resolved root.
- A `version` query parameter can replace the document subsequently served, including selecting another related version or the root itself.
- There is no owner-aware or inherited object-permission recheck for that selected document.
- `original=true` versus archive selection changes only the file handle, filename/MIME behavior, and returned bytes after authorization.
- Therefore, the source treats versions and original/archive files as representations governed by authorization of the root document.

This establishes the checked-resource behavior, but does not by itself establish a vulnerability: the intended authorization invariant may be that permission on a root governs its entire version family.
