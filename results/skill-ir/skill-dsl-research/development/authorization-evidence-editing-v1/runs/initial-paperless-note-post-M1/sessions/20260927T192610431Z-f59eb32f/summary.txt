Conclusions
- scenario%3Aviewer-cannot-add-note::entry%3Anotes-post: source_refuted — At the declared notes POST entry, PaperlessNotePermissions is the configured permission class. Its POST global check requires add_note, view_document, and change_document, and the premises state that all are present, so that global check is satisfied. The handler then performs a separate owner-aware view_document check on the target document; the premises state that the caller has object view access, so this check is satisfied. In the POST branch, before any creation, the handler performs a separate owner-aware change_document check on the same document. Because the caller is not the owner and lacks the object change_document grant, the supplied owner-aware implementation does not authorize that check, and the handler returns HTTP 403. Note.objects.create is therefore a protected side effect that is not reached in this scenario; it would create the note only after the change check passes. The fixed source supports a deny at this declared-entry boundary. No repository-wide or deployment-level completeness claim is made.
