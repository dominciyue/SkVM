- scenario%3Aversion-owner-no-root-view::entry%3Adownload: source_refuted — At the download entry, the handler delegates to file_response. That path resolves the requested document and its root, then performs the owner-aware view_document check on root_doc before selecting and serving a file. The check is therefore on the existing root document, not on the requested version document. Under the stated premises, the caller is neither the root owner nor granted view_document on the root, so the check returns false and file_response returns HTTP 403; the serving effect is not reached. If authorization had passed, the file object would be the file_doc returned by _get_effective_file_doc: for an explicitly requested version, the source routes resolution through _resolve_file_doc(root_doc, request). Ownership of that selected version is distinct and does not satisfy the root-document authorization check. This matches the accepted policy at the declared-entry boundary: the root check is required before serving any selected version. The conclusion is limited to the supplied entry and declared dependencies; it does not claim repository-wide behavior.
