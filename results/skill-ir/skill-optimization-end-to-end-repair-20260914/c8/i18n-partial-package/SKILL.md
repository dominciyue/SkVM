# 🌍 i18n-helper — 国际化/本地化助手

## 触发条件
当用户要求以下操作时激活此技能：
- 扫描代码中的硬编码中文/英文文本
- 为项目添加国际化支持（i18n）
- 批量提取和翻译语言文件
- 检查翻译完整性（缺失 key 检测）

## 工作流程

### 1. 项目分析
- 若项目提供 contract、report schema 或语义配置，先读取并将其作为本次任务的权威边界；严格遵守允许/保护文件、必需输出和精确字段集合，不凭经验添加字段。
- 检测项目类型（React/Vue/Angular/Node.js/Python/Java 等）
- 识别已使用的 i18n 框架（react-intl, vue-i18n, i18next, gettext 等）
- 扫描源代码目录结构，并确认入口初始化文件及现有语言文件。

### 2. 硬编码文本扫描
- 在 `.js/.jsx/.ts/.tsx/.vue/.py/.java/.go` 等文件中搜索硬编码字符串
- 排除：变量名、URL、正则表达式、import 路径、日志调试信息、技术术语、选择器和测试标识；除非合同明确要求，否则不要改动这些内容。
- 标记所有用户可见文本，包括 UI 节点文本、按钮/提示/错误消息以及可访问性属性（如 `aria-label`、`title`）。记录每个原文的来源文件、出现次数和原文占位符。
- 为每个条目分配稳定、非空的点分隔 key；同一条目在代码和语言文件中必须使用同一个 key，避免仅凭位置生成易漂移的 key。

### 3. 语言文件生成
根据项目框架生成对应格式：
- **JSON** (i18next/react-intl): `{ "key": "value" }`
- **YAML** (vue-i18n): `key: value`
- **PO/POT** (gettext): 标准格式
- **Properties** (Java): `key=value`

### 4. 代码替换
- 将硬编码文本替换为 i18n 函数调用；属性文本也要使用框架支持的表达式形式，不要把翻译结果写死。
- 保持原有格式、DOM 结构、行为和变量插值；按项目语义配置区分原文占位符与语言文件插值语法，并正确处理复数。
- 保留已有语言条目及其译文，只新增或更新扫描出的条目；不要用猜测性的翻译覆盖现有内容。
- 示例：
  ```javascript
  // 替换前
  alert('保存成功');
  // 替换后
  alert(t('alert.saveSuccess'));
  ```

### 5. 完整性检查
- 对比主语言文件与每个翻译文件的 key 差异，并检查每个语言条目的占位符集合与原文一致；缺失项应明确列出，不能以“未发现”代替空数组。
- 若任务提供机器可读报告契约，严格按其字段、类型、枚举、去重和顺序要求生成报告；至少核对扫描文件、原文、key、占位符、出现次数和缺失 key。
- 验证必需文件存在、JSON/语言文件可解析、代码中的 key 均能解析到各目标语言，并检查只修改允许的文件。最后用简洁报告说明仍需人工判断的翻译质量、语境和复数语义。
- 统计翻译完成度百分比（仅在任务要求时输出），不要把技术术语、URL、选择器或日志误报为待翻译文本。

## 输出格式
```markdown
## 📊 i18n 扫描报告

### 硬编码文本
| 文件 | 行号 | 内容 | 建议 key |
|------|------|------|----------|
| src/App.tsx | 42 | '欢迎使用' | page.welcome |

### 语言文件
已生成 `locales/zh-CN.json` 和 `locales/en-US.json`

### 翻译完整性
- zh-CN: 45/45 (100%) ✅
- en-US: 42/45 (93.3%) ⚠️ 缺少 3 个 key
```

## 支持的 i18n 框架
- react-intl / FormatJS
- vue-i18n
- i18next / react-i18next / next-i18next
- Angular @ngx-translate
- Python gettext / Flask-Babel
- Java ResourceBundle / Spring MessageSource
- Go go-i18n

## 注意事项
- 不要翻译技术术语（API、SDK、HTTP 等）
- 保留变量占位符 `{name}` `{{count}}` `%s` 等格式
- 复数形式和性别变体需要特殊处理
- 日期、数字、货币格式需使用 locale 感知的格式化函数
