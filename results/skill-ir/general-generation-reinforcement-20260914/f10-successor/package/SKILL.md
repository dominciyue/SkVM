# 🌍 i18n-helper — 国际化/本地化助手

## 触发条件
当用户要求以下操作时激活此技能：
- 扫描代码中的硬编码中文/英文文本
- 为项目添加国际化支持（i18n）
- 批量提取和翻译语言文件
- 检查翻译完整性（缺失 key 检测）

## 工作流程

### 1. 项目分析
- 先读取项目提供的 contract/config/output ABI（若存在），再读取 package manifest 和实际存在的源文件；contract 对框架、允许修改/保护文件、必需输出、确认规则、key/插值规则及报告字段具有优先级，示例模板不能覆盖它。
- 记录可变输入：源文件集合、框架、locale 列表、输出路径、确认标记/规则和保护边界。不要凭经验探测不存在的目录；只处理实际列出的文件或用户/contract 声明的范围。
- 若没有契约，才根据项目结构和已安装框架推断；不确定的范围保留给用户，不要擅自扩大扫描或输出范围。

### 2. 硬编码文本扫描
- 在实际存在且属于任务范围的源文件中建立“已确认文本”清单，再进行替换：只有满足项目契约的确认条件（例如明确的标记、属性或框架规则）的用户可见文本才进入清单。
- 排除变量名、URL、正则表达式、import 路径、日志调试信息、技术术语、测试选择器等非用户文案；没有契约确认的相邻字符串不要猜测为待翻译内容。
- 为每个确认项记录原文、文件、key、占位符和所属 locale，避免全局字符串替换。

### 3. 语言文件生成
根据项目框架生成对应格式：
- **JSON** (i18next/react-intl): `{ "key": "value" }`
- **YAML** (vue-i18n): `key: value`
- **PO/POT** (gettext): 标准格式
- **Properties** (Java): `key=value`
- locale 的 key 集合从已确认清单和契约规则派生，使用契约要求的精确 key；保留所有占位符。若存在 output ABI/required fields，严格按其字段、类型和允许的附加字段输出，不能把本节示例或 Markdown 报告模板混入机器可读产物。
- 一次完成契约声明的语言文件、配置/入口和报告等输出，不创建未声明的旁产物。翻译措辞、复数、性别和领域术语仍由 agent 判断，不要凭空补造语义。

### 4. 代码替换
- 将每个确认项替换为项目实际使用的 i18n 函数/组件调用，key 使用确认值本身；保持原有结构、变量插值和非文案代码。
- 只修改允许修改的源文件；保护文件只读。替换完成后把入口、locale 资源和组件调用连通，避免只生成孤立语言文件。

### 5. 完整性检查
- 所有写入完成后做一次集中的、可重复的检查：解析产物，核对必需/保护/额外文件边界、报告 ABI、确认 key 与代码调用、每个 locale 的 key 集合、占位符一致性及缺失项。没有独立检查条件时，明确列出未验证的部分。
- 验证优先使用结构化解析和简单字面包含/集合比较，不要为简单条件编写脆弱的嵌套引号正则。使用当前 shell 的原生 quoting；PowerShell 尤其避免在双引号字符串中嵌套转义引号，必要时改用单引号、`.Contains()` 或先构造变量。
- 若命令因解析/环境语法失败，先修复检查命令并重跑，不要据此反复读取或改写业务文件，也不要把 parser error 宣称为产物缺陷。检查通过后再汇总报告；将翻译质量和契约未覆盖的判断保留为 residual duty。

## 输出格式
```markdown
## 📊 i18n 扫描报告

### 硬编码文本
| 文件 | 行号 | 内容 | 建议 key |
|------|------|------|----------|
| src/App.tsx | 42 | '欢迎使用' | page.welcome |

### 语言文件
已生成 `locales/zh-CN.json` 和 `locales/en-US.json`

### 翻译完整性
- zh-CN: 45/45 (100%) ✅
- en-US: 42/45 (93.3%) ⚠️ 缺少 3 个 key
```

## 支持的 i18n 框架
- react-intl / FormatJS
- vue-i18n
- i18next / react-i18next / next-i18next
- Angular @ngx-translate
- Python gettext / Flask-Babel
- Java ResourceBundle / Spring MessageSource
- Go go-i18n

## 注意事项
- 不要翻译技术术语（API、SDK、HTTP 等）
- 保留变量占位符 `{name}` `{{count}}` `%s` 等格式
- 复数形式和性别变体需要特殊处理
- 日期、数字、货币格式需使用 locale 感知的格式化函数
