# AF handoff for AE

AF owns only the paths enumerated in `ready.json`. No index, commit, push, shared

## CLI integration

The standalone interface is:

```ts
runAuthorizationComposeCli(args: string[], io?: { stdout: (value: string) => void; stderr: (value: string) => void }): Promise<number>
```

In AE-owned `src/cli/authorization.ts`, before the local-run fallback:

```ts
if (argv[0] === "compose") {
  const { runAuthorizationComposeCli } = await import("./authorization-compose.ts")
  return runAuthorizationComposeCli(argv.slice(1), dependencies)
}
```

Help line: `compose --workspace=<workspace.json> --out=<new-directory> [--check-only]`.
Use the existing dependency object structurally; this handler accepts only stdout
and stderr and has no provider initialization. A routed integration test should
invoke `runAuthorizationCli(["compose", "--workspace=...", "--out=...", "--check-only"], deps)`
and assert exit 0, valid plan and absent output. An invalid scenario reference
should return 1 with variantId/field; unknown flags return 2. Standalone tests
already cover those contracts and runtime transitive imports.

## Shared loader coordination

AE supplied `loadLocalAuthorizationInputValue(value, inputFile)` and explicit
parent-relative sourceRoot handling in the shared loader. AF never edited that
file. Original file-based check/run still consumes generated ordinary authoring/v2.
AF first checks at the authored sourceRoot coordinate (base file unless sourceRoot
is replaced, then workspace file); publication checks staged bytes at final output
coordinates. A red/green test prevents an output move from legitimizing a junction
that escapes the original authored boundary. Neither pass checks semantic source
enforcement; both reuse existing declaration/reference/source-bound validation.

## Usage/developer documentation draft

The opt-in scenario workspace composes one common authoring/v2 base and 1-50
explicit whole-field replacement lists. `authorization compose --check-only`
returns deterministic inputs, per-field origins, coordinate relocation and
diagnostics without writing files or initializing a provider. Publication creates
a complete new directory of ordinary `<id>.json` inputs and non-semantic provenance
sidecars. Existing directories are refused, including empty ones and concurrent
creators. Source files and authored policy location text are preserved. Generated
sourceRoot is relative to the generated file; original sourceRoot is relative to
base, replaced sourceRoot is relative to workspace. Output parent must exist and
source/output must support same-volume relative coordinates.

Publication currently supports Windows only. Other platforms fail explicitly
before staging, because ordinary POSIX rename can replace a racing empty
destination; AF did not add native dependencies or claim an unverified portable
primitive. Planning is platform-independent. Abrupt termination can leave an
owned temporary sibling; crashes are not automatically resumed or cleaned.

Component/public functions live in `authoring-workspace/{schema,plan,materialize}.ts`;
the standalone handler is `src/cli/authorization-compose.ts`. The complete example
and command/reference/limitations documentation are at
`examples/authorization-assessment/scenario-workspace/README.md`.
