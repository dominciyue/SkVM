# 授权边界任务：领域语义、真实案例与评价设计定向研究任务书

> **执行方式：** 使用 `superpowers:executing-plans` 连续推进 T0–T10。主线程负责领域判断与结论，只读来源核验可按项目规则委派。普通检查点不等待确认；本轮完成后交付研究决定，不自动启动生产开发。

**Goal:** 补齐授权边界任务的跨 skill 职责映射、真实输入与判定依据、覆盖分母来源和可区分的实验假设，使下一轮能直接制定并执行最小原型计划。

**Architecture:** 已有 E 研究 → 同任务职责映射 → 真实案例/答案依据 → 领域规则与漏项分析 → 整体方法/表示方式/实现一致性分别评价 → 最小消费路径与开发决定。配置可以承载领域语言；不预设需要第二套语法，也不把两种表示等价当作整个方法失败。

**Tech Stack:** 公开 skill 与固定版本源码、维护者修复/测试/政策资料、GitHub CLI、JSON/JSONL 证据；只读核对现有 SkVM loader/run/provider/agent-loop。可做必要的数据提取与纸面演练，不修改生产代码。

- 状态：`completed-with-open-questions`；T0–T10 已完成，方法建议为 `ready-with-bounded-questions`，不自动进入开发。
- 工作分支：`skill-ir-aot`，不另开分支，只向用户 origin 发布。
- 当前研究范围：单 repo/ref、源码可见的授权/信任边界任务。full/diff/broad 审查、依赖或 secret 扫描、真实部署判断与补丁执行不是本轮支持目标。
- 唯一研究正文：[skill-dsl-research.md](../../skill-ir/skill-dsl-research.md)，重点接续第 7.7 节。不得另建本轮 research-report、design、handoff 或总结 Markdown。
- 历史依据：[E 范围决定](../../../results/skill-ir/skill-dsl-research/scope-decision.json)、[方法比较](../../../results/skill-ir/skill-dsl-research/method-comparisons.json)。保留原件，在当前研究正文说明修订，不回写 E 结果。
- 本轮优先级：**定向补证和澄清方法，而非扩大阅读规模、强行证明 DSL 更好或提前实现系统。**

## 一、必须回答的问题

1. 不同 skill 的授权职责，是否确实共用主体、资源、操作、条件和证据关系？哪些剩余职责不能迁移？
2. 用户要提供什么，系统能从源码发现什么，哪些授权政策不能根据现有代码行为推测？
3. 已声明检查项全完成、源码范围已探索、证据支持结论，分别能保证什么？漏入口或漏角色怎样暴露？
4. 真实案例的正确答案依据是什么？模型能看到哪些材料，评价者额外看到什么？
5. 下一轮究竟测整套方法收益、作者表示收益，还是入口一致性？什么结果会改变实施决定？
6. 最小运行需要哪些已有组件，是否可以先用固定源码上下文或受限只读工具完成？

完成不要求所有未知消失，不要求补满固定成员数量或获得正向结果。必须把仍未知的事项变成一个可执行的小实验或明确的缺口；不可继续用“还需调研”代替具体下一步。

### T2 — 明确领域规则及其来源

**写入：** 总文档“授权任务语义与责任”，附 observations 证据。

- [x] 用普通中文说清领域对象：谁尝试什么操作、访问哪个资源、与资源是什么关系、哪些条件影响许可、哪个入口实现这件事。
- [x] 为每项预期授权规则注明依据：明确用户需求、项目政策/文档、独立测试，或仍未知。源码行为记录为观察，不能直接变成正确政策。
- [x] 说明模型可以提议哪些对象/关系，人或宿主依据什么接受；没有政策时如何保留未知而不猜 allow/deny。
- [x] 梳理 source ref、入口发现、控制路径、候选问题、证据、复核和结论之间的关系。只定义影响本任务的语义，不扩展为通用安全语言。
- [x] 展示一个有来源的领域声明和对应自然语言说明；两者要求相同。字段使用 JSON/YAML 即可，不为展示 DSL 新造语法。

**完成：** 每个关键字段有任务含义、依据和解释责任；不是把 prose 机械拆成任意 steps/instructions。

### T3 — 落实真实源码输入与参考答案

**写入：** cases manifest、inputs、oracles；总文档只保留选择理由和结果索引。

- [x] 定向寻找适合源码分析的公开授权缺陷、维护者修复或回归测试。先核对政策与相关调用上下文，不把 CVE 标签或补丁标题直接当答案。
- [x] 准备能够区分以下行为的案例：确有源码可见越权；局部看似缺检查但上游已有控制；决定性事实在源码外，当前应保留未知。同一真实项目可提供不同版本/情形，但不能计为多个独立 skill。
- [x] 固定实际 repository URL/ref/路径，保存必要上下文，记录许可证和裁剪内容。正例与修复版本的对应关系只放 oracle；模型输入保留任务必需政策，但不给具体漏洞位置或答案提示。
- [x] 将 `abc123`/admin-export 设计例换成真实绑定的演练，或明确保留为 synthetic 并另附真实例，不把设计例升级为真实证据。
- [x] 输入与答案目录分开；记录后续 runner 应读取的允许文件集合，禁止把整个 cases 父目录递归部署给模型。
- [x] 找不到可靠真值时记录证据不足；允许合成材料验证状态规则，但不能把它当真实任务效果或独立成员证据。

**完成：** 后续执行者能拿到输入、知道如何评价及哪些结论不能判断；无需安装或执行外部项目来完成本轮取材。

### T4 — 分开声明覆盖、发现范围与结论支持

**写入：** 总文档与带案例 ID 的 observations。

- [x] 明确 declared obligations 的来源、source discovery 的实际范围、每项 evidence support；不能把三者压成一个 complete 布尔值。
- [x] 演练故意漏入口、漏角色、用户需求与声明矛盾、已检查代码变化、授权政策变化、证据失效，以及不影响判断的无关文件变化。
- [x] 对每种变化说明：谁可发现、凭什么发现、哪些旧记录失效、哪些可保留；发现不了的漏项必须承认，不让同一份清单自证完整。
- [x] 给完整性表述写出具体范围，例如“已处置声明中的 6 项；发现范围中另有 1 个入口待映射”。允许部分有效结果，未处置项不抹掉已确认发现。

### T5 — 确定语义评价与复核独立性

**写入：** 总文档；案例级答案写各 oracle。

- [x] 区分作者/发现者、重新检查者和实验评价者。独立上下文只代表程序上的分离，不保证专业独立或错误不相关；不强制真人数量，也不伪造真人审核。
- [x] 指定后续评价如何避免只见最终结论、如何核对实际引用的路径/控制、如何记录误报漏报和不支持的部署推断。
- [x] 定义正确 abstention 与过度拒绝：全部输出 unknown 不能靠没有误报算成功；明确已知案例中的完成质量和未解决比例。

### T6 — 重写可区分的实验假设

**写入：** 总文档“下一原型评价”，保留旧 E9 方案的修订理由。

- [x] 分开三类问题：整体方法是否帮助完成任务；额外作者表示是否减少错误/修改负担；多个入口是否语义一致。
- [x] 整体方法建议比较 B（信息相当的原始或整理 skill）与 D（领域声明及配套执行支持）。明确这是整套方案效果，helper 调用能力/时机若变化，作为干预说明而不是隐瞒或归因语法。
- [x] 只有存在具体可区分假设时增加 M（整理说明 + 同 helper）或第二表示臂。语言层归因时控制 helper、校验、修复、资源、模型和答案信息；没有独立假设就删除额外臂。
- [x] 表示收益从同一自然需求出发分别编写/修改，记录首稿错误、修正与成本；若作者是模型，标为模型辅助编写结果，不报人工分钟或人工节省。
- [x] 确定性 parity 只检查输入归一化和行为一致性，不承担真实效果结论。两种表示等价时停止冗余表示，不据此停止全部领域方法。
- [x] 根据 T3–T5 选择主要指标和必要质量要求：正确任务判断、漏项/虚假完成、有效证据、误报与合理未知；分别记录 token、调用、耗时和未知美元成本，不要求全部指标上升。
- [x] 提前写清支持、取舍、无差异、负向、不可判定的解释。小案例集只支持可行性观察；重复次数由拟回答问题决定，不做没有依据的显著性或跨模型承诺。

**完成：** 每个拟议实验臂都有可能改变决定的理由；不再默认建设两个必然等价的入口。
