# BT0–BT21：作者恢复、源码语义核验与方法价值诊断

> **执行模型：gpt-6-astra / high。** 用户于2026-10-21授权撰写任务书并派发新的开发线程。直接执行有限队列，常规检查点不等待确认。实施时使用 `superpowers:executing-plans`、`superpowers:systematic-debugging` 和 `superpowers:test-driven-development`，完成声明前进行必要验证；本任务书与用户授权优先于技能中的重复审批或新建 worktree 建议。

**Goal：** 修复已知宿主故障后的自动作者续作，使当前自动稿接受独立的源码行为检查；用同一组真实任务区分自动生成缺陷、材料整理价值和执行工具增量，交付普通入口可用的修复与可判断下一步的方法结论。

**Architecture：** 复用现有 inquiry/native 入口、账号 adapter、持久 checkpoint、有限程序执行器、source relations、obligations、trial、结果投影和证据归档。新增工作集中在恢复接线、源码与程序的差异检查、两种跨任务关系以及小型诊断对照。参考材料只用于独立方法诊断，自动作者与参考材料保持独立来源。

**Tech Stack：** TypeScript/Bun、现有 Zod 合同与测试、官方 Codex 账号通道；必要时用隔离 Go 工具链对固定上游源码运行局部测试。没有新的服务、页面、平行 CLI 或通用语言解释器。

## 二、已核实根因与本轮改变

1. **作者恢复断在宿主。** BS A-G恢复回合已完成并保存四份提交，随后候选投影发生 TypeError，正常作者续作没有发生。共享 owner 修复已在 `c3be4cc2`，BS按旧队列停止作者，后续六个消费者仍使用不完整末稿。这同时涉及实现恢复和实验编排，不能全部记作模型编写能力不足。
2. **源码引用有效，行为仍会错。** M最后30步在29案有限值/条件上匹配，三个先后顺序反例失败。G最后7步的 permission 字段形状有误，且没有完整创建、close、refetch、converter链；只改格式仍补不出这些业务语义。
3. **执行确实发生，但收益很小且有退步。** BS四个E都收到并使用计算结果。N/R/E各24个评价域分别14/14/15完整，全部整题0/12；G0-E还错误排除了父路由门槛。不能再把问题泛称为“没有调用工具”。
4. **已有调查投影主要提供线索。** `program-obligations`、call relations和候选目录已经存在，但读过、关联到问题、能执行都不能单独证成入口激活、对象一致或错误顺序。继续堆更多字段并不能补这层。
5. **实验需要分开两种问题。** 自动生成好不好，与可靠程序/关系材料有没有帮助，是两个待测问题。BT允许明确标记的独立参考材料诊断方法上限；不会把它包装成自动生成成功。

本轮先保证有可靠的检查依据，再修共享生成过程；保留局部执行，重点判断“入口/守卫是否约束当前效果”和“调用、效果、错误的先后关系”。不追求完整复制 Memos/Gitea 业务，不扩 Download 付费面板，不增加 Go/Python 通用语义。

### 3.2 三条证据轨道

| 轨道 | 来源与用途 | 可以支持的结论 |
|---|---|---|
| 自动稿 A | 模型从BS末稿及真实源码修订，所有提交原字节保留 | 自动编写与正常修订能力 |
| 独立参考 R | 开发者依据源码与局部测试整理，明确记录人工/AI辅助及制作步骤 | 有可靠材料时，当前方法能否发挥作用；不计自动生成成功 |
| 源码检查 O | 独立于DSL执行器的上游函数测试、源码关系及评阅 | 在明确范围内发现语义差异；不把相同手写规则的自比较叫独立验证 |

R可以包含与任务相关的有限程序及关系材料；只覆盖可核验的范围。保留原题全部职责，范围外部分仍由消费者读源码分析。R不包含最终任务答案、评分表或预期标签；它仍是经过准备的语义材料，N与R比较必须计入这种信息与准备差异。

源码测试优先在固定完整checkout中运行原函数和原类型；外部存储/网络以接口fake隔离，记录实际调用序列与首错。可以加测试文件和观测点，但不得重写待测控制流。无法直接调用而必须抽取函数时，记录抽取与shim，标记为抽取测试，限定证据范围。手写参考解释不称真实源码执行。

不启动目标服务，不访问真实业务数据库或执行真实写入。隔离测试执行原函数要单独计为 `isolatedSourceTestExecutions`，不能仍把所有目标代码执行写成0。

### 3.3 检查范围

- **入口与效果关系：** 当前路由/主体条件是否激活所述guard，guard约束的主体、资源与当前效果是否一致。helper存在不自动证明可达、必经或有效。
- **顺序与失败关系：** 哪个调用先发生，首个错误在哪里，效果请求/效果完成/数据库提交分别已知到什么程度；后续失败不抹掉已发生的效果。
- **程序解释正确性：** 有效JSON、当前源码绑定、有限输入结果、轨迹顺序分别报告。
- **自然回答质量：** 原问题的核心授权关系、实质性错误、证据依据、完整性分别评价。无关调用没有完全模拟，不阻止已有依据的局部答案；未观察到检查也不直接判为安全。

新的共享字段或小模块只有在现有类型确实无法承载时添加，先说明原因和两个匿名结构用途。源码差异检查、参考制作与原题oracle留在research层；生产代码不认识仓库名、已知答案或BS案例名。

必须先写并实际跑失败测试，再实现：

1. provider已完成且patch已持久化，后续宿主投影抛错；修复后恢复同一作者，保留最后raw及已花预算，继续产生当前有效修订。
2. 请求仍active/unknown时恢复不派发；缺少累计预算时不重置为新预算。最新拒绝提案不冒充当前已采用稿，也不静默回退最高分旧稿。
3. 仅移动路径可恢复，源码变化撤回依赖结论；来源/线程/用途不匹配给具体诊断。
4. 先调用store再拒绝，与提前拒绝得到同一返回：值相同但轨迹核验必须指出差异。
5. effect成功后refetch失败，与effect从未调用：结论不同，持久提交未知仍未知。
6. guard在未注册/未激活路由上，或校验另一资源：不能当当前效果的已满足保护。
7. 无调用证据或来源窗口遗漏：返回具名unknown，而非机械补“安全”。
8. rules只显示同一材料；execute显示该材料的真实执行/检查；两者不混入oracle或不同问题。

已有 `executable-contract-entrypoints.test.ts`、`codex-account-session.test.ts`、program相关测试和CLI测试可扩展。不要用几十个重复字段断言替代以上行为反例。测试命名和真实新增文件在BT1确定并写入状态，不能等实验失败后才补设计。

## 五、有限实验设计

### 5.1 十个正常用途

| 用途 | 数量 | 内容 |
|---|---:|---|
| A-M、A-G | 2 | 各从BS最后raw出发，真实普通作者修订；不是从空稿泛化实验 |
| N-M、N-G | 2 | 原skill、原任务、相同源码，只读源码基础工具，无领域程序材料 |
| RR-M、RR-G | 2 | 同样任务与源码，加独立参考材料的rules视图，无执行结果 |
| RE-M、RE-G | 2 | 与RR逐字节相同的参考材料，加实际执行与关系检查 |
| AE-M、AE-G | 2 | 消费各自最后自动稿，执行与检查能力和RE相同 |

M消费顺序N→RR→RE→AE；G相反。先后差异与模型/环境变化记录。不得为取得正向值更换任务、输入或最后稿。

只有自动稿存在明确可执行、源码相关的部分且没有**已知会误导该消费问题**的核心反例时，才派发AE。其余能力可以partial，不要求整题先full。无效/已知错误自动稿的AE位置记零调用资格失败，原分母保留；RR/RE仍可独立诊断方法，不再让坏作者卡死所有研究。普通用户仍可inspect坏稿和错误，不能静默包装为可用参考。

参考材料也须先通过其声明范围的独立检查；不合格则修参考并记录，无法核验的范围显式unknown。不能通过删掉原题或隐藏困难分支来达成“可用参考”。R的制作投入、允许人工准备和使用范围在派发前登记。

每个作者正常有初回合和至多两次有针对性的续作，共享同一总预算，不是每次重置。这是基于既有草稿的修复实验，全部反馈、修改和失败计入准备成本。

### 5.2 四个具名确认上限

全队列至多4个额外确认用途，用于已定位共享故障修复或有证据的原作者恢复。自然答案仅较差且没有可操作根因时，不重复抽样。影响RR/RE公平性的修复须同epoch重跑两者，占两个名额；不足时只作诊断，不拼接跨epoch优势。首件、修件和离线纠错分列。

BT内部的已知终态恢复继续原预算；BS旧记录不被改成BT请求。BT作者可加载BS raw作为起点，明确归为新修订用途及新增费用，不能称恢复了不可观测的旧配额。所有旧unknown维持封存。

### 5.3 公平性与评价

- 消费者共用完整skill、原题、事实、允许源码、模型、共同工具/时间/材料预算及答案原则。RR/RE参考材料完全一致；AE/RE差异是材料质量，不能归因执行器。
- 建议沿用BS实际宿主预算：64工具、786432展示字节、33554432读取字节、2700000ms。接管先核对；若需要调整，首次实验前统一登记，不能中途单臂扩额。材料和续作计入同一预算。
- 官方账号 `gpt-5.6-sol/high`；第三方付费API继续暂停。未知请求只读核查；认证/额度拒绝暂停该通道，重复路由失败不得创建新身份绕过。
- 准备时以源码先定核心授权关系和严重错误清单，保留BS原题及完整性量规；新主指标需在首次调用前写明。不能事后用容易字段替代原题。BS评分不回填。
- 主表至少给：核心关系正确/错误/未覆盖，严重无依据主张，原题逐问/整题完整，程序字段与轨迹，工具真正执行/采用，首答/终答，全部计划位置与失败。
- RR→RE只检验同参考材料的执行/检查增量；AE→RE诊断自动生成差距；N→RR包括整理和准备，报告为有准备辅助，不能称DSL表示本身优势。
- 两个已暴露任务的一次比较是定位性证据。允许报告明确局部改善，同时列出退步；不凭一次无差异判定所有DSL无效，也不凭局部正向宣称该类全部成功。
- 输入包含cache-read一次，输出、恢复、失败、源码获取、隔离测试、参考制作和开发代理成本分别记录；不可知费用保持unknown。

### 5.4 失败即时处理

遇到异常先定位是宿主、通道、作者程序、源码依据还是回答遗漏。共享故障当场红绿修复，停止继续使用同一坏实现；已知终态作者按照恢复规则继续。两次同根因修复无实质改善时停止该位置、给出责任，继续独立工作。不能为跑满队列或等待凑时长重复调用。

原源码局部测试环境搭建优先做最小可运行函数。一次明确依赖修复后仍需大规模数据库/框架工程时，停止扩建测试环境，改用明确标记的源码关系评阅保留未知，继续作者/方法工作。预计投入超过约2小时先重新评估范围并记录决定；不是到点自动删除原件或等待凑时长。

## 七、方法决定与验收

| 观察 | 对本轮的判断 | 后续代码方向 |
|---|---|---|
| 可靠参考RE改善核心判断，自动AE仍错 | 可执行辅助存在局部潜力，自动生成是主要缺口 | 针对已定位的源码→程序差异修生成/检查，不继续扩大消费者 |
| RR与RE近似，RR较N有帮助 | 当前价值主要来自整理过的关系/证据 | 强化通用取证与关系材料，保留必要执行，不主张执行本身获胜 |
| RE比RR更差 | 投影/执行结果对原题形成干扰，或参考也有语义问题 | 查实际使用和错误来源，收窄强制执行展示，保留原题与源码调查 |
| 自动AE已忠实，但仍遗漏原题 | 生成链改善，回答与调查组织仍缺 | 修同一来源的问答组织，停止把自然遗漏都归为程序不够长 |
| 自动、参考都无法核验关键关系 | 当前表示/检查范围不足 | 交付有依据的局部能力和具体缺口，暂停同形面板，重新判断任务范围 |

这些是发展决策，不是预设的胜负。不得把两个任务的持平变成整个路线的定论。

BT实际决定：普通恢复、关系检查和局部M修复已达到工程与诊断最低目标。G作者在只有converter符号候选、没有正文时写入错误规则；M自动稿局部正确后，消费回答仍遗漏原题职责。下一责任分别落到既有源码读取与`program-authoring-context.ts`依据反馈、`program-consumption-context.ts`原题覆盖组织；这是后续方向，不是本轮追加实现或新实验授权。参考准备成本未知，不能把局部域增量与token比合成为净收益。
