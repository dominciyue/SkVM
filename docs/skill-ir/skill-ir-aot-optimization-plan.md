## 1. 首个原型：子流程能接续

**交付目标：** 一个普通 bare-agent 任务里，固化程序完成一段工作后继续剩余任务；程序异常或结果不合格时，模型接收到有效中间状态，完成剩余工作。先用确定性测试验收，然后才运行少量真实模型配对。

### 1.1 先写失败测试

针对实际观察到的缺口，覆盖以下情况；不制造一套脱离普通入口的模拟成功链。

1. T1/T2 成功：实际结果进入 trace/history，后续模型仍被调用；没有把子流程误判为整题结束。
2. 退出码为零但产物不合格：结果不作为成功交付；恢复模型看到检查诊断。
3. 第二步失败：第一步已验证的产物仍可用，失败步骤及依赖它的结果标为不可用；恢复不重复第一步的效果。
4. 输入或依赖改变：旧候选失配走普通流程，不能静默使用旧结果。
5. 恢复后完成或再次失败：都有真实终态、完整调用与耗时，失败不记为零成本。
6. 原有 T0 和整任务 replace 行为兼容；mock 能观察实际循环次序和工具结果，而非只校验返回对象形状。

### 1.2 共享实现责任

| 文件/模块 | 改动责任 |
|---|---|
| `src/runtime/types.ts` 及 hook 调用方 | 明确子流程成功、带状态恢复、整任务完成的区别；设计紧凑检查点和剩余职责 |
| `src/adapters/bare-agent.ts` 及其已有 agent-loop 接口 | 把结果/失败状态接入真实历史与 trace，保留实际 iteration；避免 replace 直接结束剩余任务 |
| `src/jit-boost/solidifier.ts`、`src/jit-boost/types.ts` | 从工具执行后形成候选证据；输入/依赖检查；结果验证；成功/失败接续；完整计量 |
| 现有 trace、包与 validation 组件 | 按现有接口复用，遇到具体缺口再补；不平行创建第二套运行器 |

编辑前定位现有测试与 adapter 的消息合同，按照失败测试→最小实现→定向回归推进。先保证一个本地、无远端效果的子流程；不要求第一版支持所有 harness，也不把 harness 不支持伪装成任务不适用。

### 1.3 本次实现约定

- `beforeLLM` 新增 `continue`，与旧整题 `replace` 分开。接续发生在 agent-loop 的真实派发边界，记录本地工具结果和检查点，随后调用模型；传递真实轮次。
- 复用 JIT candidate/persistence 入口，增加可选的有序 `subworkflow`。第一版显式启用，以参数数组执行本地命令；每步声明产物检查，旧模板保持原行为。签名命中不能自动把新子流程提升为已验证候选。
- 检查点携带通过检查的步骤、产物位置、失败原因和剩余职责。失败步骤恢复它所声明的输出文件到执行前状态；停止后继步骤，保留已验证前缀。限声明完整的本地文件效果，暂不承担数据库、远端操作或未声明文件的回滚。
- 静态依赖可绑定内容摘要，失配时交回普通执行；不同运行重新读当前输入，不跨运行复用旧产物。每个新子流程在一轮任务内最多自动执行一次，避免恢复后再次触发前缀。
- 测试直接走 `BareAgentAdapter`，观察模型收到的消息、真实文件和工具次数。新增测试放 `test/runtime/subworkflow.test.ts`，回归已有 bare-agent、agent-loop、solidifier 和 durable trace。分类选择器、自动编写和跨 harness 恢复后续另做。

本次增加的是现有 `run` 命令的 `--subworkflow` 开关，并提供[可运行例子](../../examples/tiered-solidification/README.md)，没有另建 CLI。普通入口已验证的成功/恢复链使用脚本替身；官方账号 adapter 仍绑定旧授权研究，需要先接通通用模型消费，再开展第 3 节配对。已有 JIT 自动晋升保留为旧基线；新子流程暂由显式选择启用，工具后证据驱动的自动晋升随第 2 节开发。

确定性核验：10 项新接续测试覆盖本节六类情况；相关 100 项测试、323 项断言通过，另外 durable trace 4 项/17 断言、授权 adapter 3 项/14 断言通过，共 107 项测试、354 项断言；主类型检查通过。文档单测 15 项、目录检查 21 条目通过；40,477 文件扫描无 broken/legacy/governance error。这些是工程证据，不是新模型效果实验。
