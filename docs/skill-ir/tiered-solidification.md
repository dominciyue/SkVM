# 基于 Skill 分类的分层代码固化 Agent 运行时优化机制

Category-Aware Tiered Code Solidification for Agent Skills。更新于 2026-10-29。

本文承载新课题的方法、相关研究和开发判断。当前状态见 [current-status](current-status.md)，实施顺序见 [plan](skill-ir-aot-optimization-plan.md)，历史数据见 [evidence-index](evidence-index.md)。本地子流程的检查与状态接续已有首个显式原型；分类选择和真实模型效果仍待实现、测量。

## 1. 目标和问题

用户提供 skill、自然任务和工作目录，按平常方式运行一次。系统观察哪些步骤规则稳定、依赖清楚、结果可检查，把合适的部分转换成可复用程序。下一次运行时，程序接管这部分工作；检查失败，则把已经完成的工作和失败位置交回模型，让它接着做。

分类要回答的是“适合固化什么、如何检查、失败后怎么接续”。同一 skill 可以含多种任务和子流程，类别不应成为一张整包放行表。研究对象从授权 DSL 回到通用运行时；授权程序作为一种历史实例和验证器资产保留。

主要问题有三个：

1. 类别和运行证据能否选出比固定粒度更合适的固化范围？
2. 程序检查失败后，保留有效中间结果能否减少重做，同时避免错误结果进入后续步骤？
3. 算上分类、编写、检查、失败恢复和缓存后，在输出质量不下降的条件下，实际节省多少时间、token 和模型调用？

“保证正确性”落实为两层：可检查的硬约束必须满足；语义质量用任务独立评价和事先规定的非劣标准检验。LLM 接手并不自动保证正确，恢复后的最终结果同样要评价。未验证、未交付和错误均保留在端到端分母中。

### 2026-10-29 执行证据与普通账号

默认 JIT 在 `beforeTool` 捕获来源快照、调用参数和产物状态，在匹配的 `afterTool` 核对退出 0、全部声明产物创建/更新及内容检查后累计观察。重复回执、错误内容和旧文件不晋升；旧无证据晋升状态会降回未验证。`promotionPolicy: legacy-signature` 才启用历史签名基线。观察时串行检查每个工具，避免下一写入覆盖上一回执的产物。

共享 `artifact-checks.ts` 提供文件/JSON 结构、JSON pointer 数值 sum/count/equal、原始字节或保护片段多重集保存检查。`command` 评价器声明 numeric/preservation/semantic 范围，返回 passed/failed/unknown、依据和可选 usage；失败退出或无有效结论记 unknown。每份报告保留范围、耗时和产物摘要；翻译含义仍需独立评价器，保护片段一致不证明翻译质量。检查失败或 unknown 使子流程撤回失败步声明输出、保留有效前缀并交还模型。

普通 `codex-account` 无需授权 inquiry scope，复用官方 CLI 会话和普通主机工具；支持 skill 注入/发现及显式子流程。子流程在真实 turn/start 前执行，检查点进入该回合上下文；工具按执行顺序生成回执。工具预算耗尽后拒绝新工具，但等待同一回合交付或原定超时，不另发请求。旧授权入口维持原有预算/收尾合同。CLI 原生工具隔离不等于普通主机回调被沙箱隔离。

真实故障确认在 `results/skill-ir/tiered-solidification-20261029/failure-confirmation/`：错误 sum=99 被检查器撤回，账号模型从保留前缀修复为 6、完成报告，真实 completed/delivered，前缀一次。首轮因预算关闭未交付，原件保留且只读查得 interrupted。内部模型调用数与 USD 未知；这是手写候选的开发接线证据，不是自动优化或效率收益结论。

### 2026-10-28 本地原型

[subworkflow.ts](../../src/runtime/subworkflow.ts) 执行候选声明的有序命令，每步核对文件存在、最小字节数、JSON 可解析性和必要字段。非零退出或检查失败会恢复该步声明输出的执行前字节，保留已验证前缀，停止后继步骤。恢复失败的产物撤回有效标记，给出具体诊断。静态依赖绑定失配交回普通流程，不使用缓存结果。

候选复用 JIT 的 schema 与保存接口，经显式 `run --subworkflow=<candidate.json>` 启用。首版只支持普通 bare-agent 的本地文件流程；参数来自显式/regex 提取，避免额外模型提取调用不计入主账。新子流程不会因为签名重复就自动晋升，每次任务最多在首轮启动一次。旧 JIT 模板行为继续保留为基线。

这次把真实文件操作放进普通 `executeRun → BareAgentAdapter → agent-loop`：成功和故障示例均生成三行、合计 6 的报告，前缀各执行一次；故障例第二步退出 0 但缺必要字段，检查后撤回再接续。模型侧是脚本替身，实际模型请求为 0。测试同时覆盖中途交还的历史顺序、依赖变化、回滚、模型恢复失败、超时不再派发及旧 replace。复核发现并修复了工作目录异常被静默降级、恢复后的有效文件仍被列为失效的问题。

检查点与完整本地工具结果留在 RunResult.steps；durable trace 新增 `subworkflow-checkpoint` 事件，记录进度与失败原因。普通使用和重跑见[示例](../../examples/tiered-solidification/README.md)。此版检查是结构层约束，业务语义检查器、自动候选/类别选择、跨会话恢复和真实模型收益仍是后续工作。命令必须声明全部可变文件输出；未声明写入、数据库和远端操作没有回滚保证。

### 最接近工作的代码核对与研究定位

2026-10-28 进一步检查了 Adaptive Skill Granularity 的公开 [router](https://github.com/Jayceon-3/Adaptive-Skill-Agent/blob/master/granularity_router.py) 和 [FSM executor](https://github.com/Jayceon-3/Adaptive-Skill-Agent/blob/master/step2_fsm_executor.py)。前者组合 mode/recovery 两个预测，模型缺失时按任务类型回退；后者会提供当前工作区和失败信息，切回 primitive tools。当前状态恢复也已有实现先例。其类型元数据如何取得、已验证与可能污染的数据如何区别，才是本项目要具体比较的问题；不把外部代码名中的 oracle 自动解释成答案泄漏。

**创新点目前是待验证假设。** 编译、宏/微选择、带状态恢复均有相关工作。拟检验三项增量：类别是否帮助选择有效且成本合适的验证器；真实数据依赖是否帮助切出更合适的程序边界；验证后保留状态是否比保留全部工作区或整段重做更可靠。需与现有机制配对测量，不能仅以跨类别组合这些组件宣称创新。

SkillSmith 作为编译与恢复的主要外部参照，Adaptive Skill Granularity 作为粒度和恢复参照；TraceCompiler 用于依赖规则对照，Agent JIT 用于前后条件与成本选择。复现先核对可获得实现、许可证、环境和模型差异：接口不兼容时报告机制复现，避免把改写版本冒称原系统。主线保持 SkVM，暂不移植整套外部框架。

## 4. 分类：任务用途与运行特征分开

分类单元是任务中的候选子流程；skill 层保留多个标签。初始用途类别如下，是研究工作分类，不是现成能力清单。

| 用途类别 | 例子 | 优先尝试的固化/检查 |
|---|---|---|
| 结构化转换与提取 | CSV 清洗、配置变换、接口样例构造 | 字段/行级程序；schema、计数、保存约束、差分测试 |
| 约束产物构建 | 文档、PPT、带模板的报告 | 脚手架与格式操作；可解析性、结构/引用/版式要求；内容判断保留给模型 |
| 规则驱动的工具流程 | 环境检查、明确规则的数据处理与工具组合 | 有界步骤图；输入前置条件、结果契约和效果确认 |
| 语义判断与开放内容 | 授权评估、翻译、选题、内容设计 | 固化检索/统计/渲染等机械部分；核心判断继续由模型完成并独立评价 |

每段再记录运行特征：输入/输出类型、数据来源、控制分支、环境和源码依赖、是否读写外部状态、结果是否可独立检查、失败后的可恢复状态。写服务、发消息、操作数据库是额外的效果属性，不混成一个互斥用途类。

一次真实 trace 能证明该次经过的路径，不能证明其他分支都稳定。重复的命令文本也可能依赖当前时间、网络、目录状态或隐藏文件。来源不能唯一归属的值保留未确定；避免把示例常量误固化成业务规则。

类别提供初始选择倾向，具体能否执行由本次输入、依赖和验证覆盖决定。先用可解释的规则选择，积累数据后再判断是否需要学习型路由器。

### 分类怎样产生，怎样证明有用

先用原始任务和 skill 说明标注用途，再用实际工具结果补运行特征；标注时不看优化后的得分。模型可提出分类与候选，但运行器自行收集退出状态、文件变化和依赖，用户无需填写 trace 或字段表。混合用途按子流程分别标注，不强制整包单选。

初版区分“已观察一次”“在登记变化下验证”“动态/尚不明确”，不从一次命令成功推导统计确定性。输入值、前序产物、程序常量、环境值分别记录来源；同字符串、同文件名或相邻调用只是线索。随机种子、当前时间、目录已有文件和网络响应也可能改变输出。

先复核已暴露的 [30 张任务卡](../../results/skill-ir/skill-task-dsl-preparation-20260919/structure-cards.jsonl)，再针对分类缺口补公开开发来源。停止扩分类的条件是：现有任务都能说明为什么选该验证/恢复方式，且新增维度确实改变一个选择；否则合并或去掉维度。类别准确率、人工一致性和运行收益分别报告，尚未做人工标注时不声称一致率。

路由只使用执行前可取得的信息。固定候选池与验证器池，比较“运行特征”与“类别＋运行特征”；两边获得同样的候选机会和检查结果。另行比较类别辅助生成验证器的收益，避免把额外手工测试误算成标签的贡献。

## 5. 粒度、验证和恢复三条独立轴

| 粒度 | 接管范围 | 适用前提 |
|---|---|---|
| T0 | 原 agent 流程 | 没有可靠候选，或执行/检查成本不合适 |
| T1 | 单个操作 | 参数来源明确，效果与结果可观察 |
| T2 | 一个有界子流程 | 步骤依赖和出口明确，可把中途状态交回 |
| T3 | 一个完整的有界任务 | 所需分支及最终结果有相应验证依据；其余输入仍回 T0/T1/T2 |

T3 不表示“高质量”，只表示覆盖范围更大。一个 T1 也可能需要严格的外部效果检查。验证分别选择结构约束、保存/完整性约束、差分依据或语义评价，明确各自未覆盖什么。

候选来源顺序：已有 skill 脚本 → 轨迹中可参数化的程序 → 模型生成局部程序。保留模型负责的余下职责，不把整包缩成一个结果文件。运行时不能把编译期已暴露答案当作业务输出模板。

### 第一版选择规则

1. 从工具执行后的有效观察建立候选。未知输入绑定或未完成的执行，不成为已验证证据；程序本身仍可保存为草稿。
2. 先检查当前输入、依赖和输出验证能力。候选不可用时直接保留 T0；仅某段可用时允许 T1，不要求整题可固化。
3. 只有相邻段之间的数据依赖明确，且中间没有未处理的语义决定或不可恢复效果，才合并为 T2。模型决定先保留，决定完成后的机械后缀仍可成为下一候选。
4. 在可用粒度中比较预计省去的调用与新增提取、检查、恢复和编写摊销成本。证据少时报告区间或成本未知，先试小边界，不虚构失败概率。
5. 执行器保证一次候选不会因恢复再次自动触发；输出和剩余职责进入普通历史。用户继续用原 skill 和自然任务，不需要维护一套独立 DSL。

初期使用线性有界片段和现有脚本，依赖表负责标明输入来源与失效后果。无需先实现通用 DAG 语言、全语法静态分析器、学习型路由器或新的工作台。

### 状态交还合同（首版本地文件实现；其余为设计）

检查点放在可解释的步骤边界，记录：本次任务与输入、已完成步骤及验证结果、当前有效变量/文件、失败步骤与诊断、尚未完成职责、效果回执和依赖版本。

成功子流程的工具结果进入普通 trace，agent 继续处理剩余任务；完整任务经最终检查通过才结束。失败时保留已经验证的前缀，撤回失败步骤及依赖它的结果，给模型一份紧凑的当前状态，必要原件通过路径读取。

本地输出可先写暂存区、检查后发布；已发生的外部效果要有回执，完成状态未知时不自动重发。恢复不意味着默认再执行整个前缀。模型接手后的新增调用、耗时和结果检查全部归入这次运行。

需要区分：输入不适用、程序异常、退出成功但结果错误、依赖变化、外部效果未知、恢复后仍失败。只有格式错误的失败与语义错误分别分析，但二者都属于用户实际付出的端到端成本。

“已验证”必须带具体检查范围。JSON 字段存在只支持结构有效，不能让模型以为内容已正确。依赖某个未验证值的产物也不升格为有效状态。首版先保留通过相应任务检查的线性前缀；跨支路选择性恢复在真实案例需要时再加。晚期报错时先使用已有最终验证结果，若任务已经完成则直接交付，避免机械地回模型重做。

## 6. 如何证明有用

主要比较按类别报告，按同一 skill/任务/输入/模型/harness 配对。开发材料与最终测试分开；旧 Download/Memos、旧 CSV 和 I18n 等已暴露输入只能用于开发或历史复验。

| 条件 | 用途 |
|---|---|
| 原 skill＋原 agent | 用户实际基线 |
| 现有 SkVM JIT | 判断是否只是重现已有能力 |
| 同候选/同验证器的固定粒度 | 判断选择粒度的价值 |
| 类别＋运行特征的选择策略 | 新方法的整体效果 |
| 去类别、保留运行特征；失败全重做对比状态接续 | 分别检验分类和恢复的贡献；在离线可控场景进行 |

先做两个或三个结构明显不同的类别，每类多个 skill 和变化任务；规模按[计划](skill-ir-aot-optimization-plan.md)逐阶段安排。样本选择依据任务结构，保留短任务、不适用输入和弱验证任务，避免只选会加速的长流程。公开 skill、研究者编写任务、真实用户任务、合成边界和人为故障分别标注；真实 skill 加人工输入仍是构造实验。

质量评价先登记各任务必需条件和语义量表；预先确定非劣界限，报告差值和不确定性。小样本先报告逐项结果，不用“无显著差异”证明质量不降。正确结果、未交付、合理拒绝和错误分开列出，拒绝不能计为任务成功。

运行指标包括端到端 wall time、真正派发的模型调用数、完整 input/output/cache、工具执行和检查时间、恢复次数及成功率。provider 的 cache 字段按定义计一次；节省调用必须计入分类、参数提取、模型检查与恢复的调用。USD 未报告时保持未知。

编译/作者/本地验证成本单列，并给出首次使用和多次复用的摊销结果：`总成本 = 编写与验证成本 + 各次运行成本`。token、时间、费用分别算，不能随意相加。失败运行进入总量；成功配对的加速比作为附表，不替代全队列统计。

正向主张应是“在某类任务、某输入范围内，通过所列质量评价，延迟或调用量改善多少”。某项更快但质量下降，或恢复频繁导致总成本增加，应记录取舍/负结果，不继续靠扩预算掩盖。

### 三个可证伪的判断

- **H1，分类有用：** 相同候选/验证器下，类别辅助策略能改善选择及端到端质量—成本表现。如果与纯运行特征策略相当，则分类只保留为组织和解释方式。
- **H2，保留状态有用：** 与整段重做、保留全部工作区相比，任务独立检查后的状态接续减少重复操作且不传播错误。故障覆盖第一步失败、中途错误、晚期报错但已完成，以及退出成功却语义错误。
- **H3，自动链有用：** 从自然任务和真实 trace 自动产生的候选能在变化输入上被实际使用。手写参考候选用于定位执行器上限，单列结果；不能替代自动生成分母。

评价器不能仅复用作者为候选生成的自测。任务需要条件由原需求先确定，最终评价尽量复用独立工具/计算/视觉或盲评；候选作者不接触封存的答案和评测输入。先检验质量，再分析延迟与调用；编写成本的盈亏平衡按预计复用次数计算，若每次都更贵则没有有限的摊销平衡点。

## 7. 现有结果如何继承

- U 阶段四组成对任务 checker 均为 4/4；耗时下降 56.79%，输出 token 下降 75.66%，但总 observed token 上升 60.59%。它证明有可用局部路径，也说明不能只看输出 token。见 [U effect report](../../results/skill-ir/trace-guided-skill-optimization-20260913/u6/effect-report-all.json)。
- G 阶段覆盖四个 skill、九次自然消费，八次独立评价中五次通过；严格 I18n 配对的 input 降低，但整体仍 mixed。见 [G final report](../../results/skill-ir/general-skill-optimization-20260913/final-report.json)。
- BU 的 Memos 有限源码差分让匹配项从 14/30 变为 23/30，反例及未知下降；这是局部检验与修稿价值。它没有证明新课题的跨类质量、状态恢复或运行时净节省。见 [BU summary](../../results/skill-ir/skill-dsl-research/development/authorization-source-differential-v1/summary.json)。

旧授权 DSL 的自然答案面板不再作为主线反复扩展。保留有限程序、检查器和失败案例；新原型优先补普通运行时的中途接续，而不是继续把 Download 解释得更细。
