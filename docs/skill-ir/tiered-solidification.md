# 基于 Skill 分类的分层代码固化 Agent 运行时优化机制

Category-Aware Tiered Code Solidification for Agent Skills。更新于 2026-10-28。

本文承载新课题的方法、相关研究和开发判断。当前状态见 [current-status](current-status.md)，实施顺序见 [plan](skill-ir-aot-optimization-plan.md)，历史数据见 [evidence-index](evidence-index.md)。本次完成研究与治理，下面的分层选择及状态交还机制仍是待实现、待验证的设计。

## 1. 目标和问题

用户提供 skill、自然任务和工作目录，按平常方式运行一次。系统观察哪些步骤规则稳定、依赖清楚、结果可检查，把合适的部分转换成可复用程序。下一次运行时，程序接管这部分工作；检查失败，则把已经完成的工作和失败位置交回模型，让它接着做。

分类要回答的是“适合固化什么、如何检查、失败后怎么接续”。同一 skill 可以含多种任务和子流程，类别不应成为一张整包放行表。研究对象从授权 DSL 回到通用运行时；授权程序作为一种历史实例和验证器资产保留。

主要问题有三个：

1. 类别和运行证据能否选出比固定粒度更合适的固化范围？
2. 程序检查失败后，保留有效中间结果能否减少重做，同时避免错误结果进入后续步骤？
3. 算上分类、编写、检查、失败恢复和缓存后，在输出质量不下降的条件下，实际节省多少时间、token 和模型调用？

“保证正确性”落实为两层：可检查的硬约束必须满足；语义质量用任务独立评价和事先规定的非劣标准检验。LLM 接手并不自动保证正确，恢复后的最终结果同样要评价。未验证、未交付和错误均保留在端到端分母中。

## 2. 已有基础与真正缺口

| 资产 | 目前实际能力 | 新课题怎么用 |
|---|---|---|
| SkVM adapter/runtime hooks | 普通运行、工具执行、轨迹和日志 | 复用入口，不另造 CLI 或 agent 平台 |
| JIT solidifier | 观察工具模式、提取参数、模板执行、失败降级 | 作为现有基线；重复次数不能充当语义正确性证据 |
| Trace 优化与包生成 | 从真实运行提案、局部代码、验证和包导出 | 候选程序来源，优先复用现成脚本 |
| API/Env 确定性组件 | 特定支持范围内的构造与独立检查 | 作为类别内可复用验证能力，不扩写为所有 skill 都支持 |
| 授权可执行程序 | 有限执行、事件检查、源码失效、局部差分反例 | 复用检查/失效思路；不再把授权解释器扩张作为主线 |
| 分类研究与公开 skill 来源 | 52 个登记包、24 个深读 skill、30 张任务卡 | 已暴露的开发材料；重新按新问题标注，不当作新测试集 |

### 运行时审查发现

- [solidifier.ts](../../src/jit-boost/solidifier.ts) 的 `afterLLM` 按工具签名连续命中晋升；这个时点尚不是工具成功及产物验证后的观察。执行模板后主要按退出成功判断，缺少类别对应的输出检查。
- 同文件失败路径做降级并返回 passthrough，没有完整的已执行前缀、产物有效性和失败状态交还合同。
- [runtime/types.ts](../../src/runtime/types.ts) 的 before-hook 只有 passthrough/replace；缺少“完成一个子流程后继续”和“失败后带状态继续”的明确含义。
- [bare-agent.ts](../../src/adapters/bare-agent.ts) 的 replace 会成为无工具调用的结束响应；返回的 hook 工具结果没有作为普通执行历史完整接回。hook 观察使用的 iteration 也需要与实际循环统一。

因此第一项工程验收应是“成功子流程接着做剩余任务，失败子流程从有效状态接着做”。先不增加新语言语法、分类模型或大规模实验面板。

## 3. 相关研究与借鉴范围

下表于 2026-10-28 核对原始论文/项目资料。近期预印本按其公开实验范围使用，不把作者报告直接当作本项目效果。

| 工作 | 可借鉴内容 | 与本课题的关系及证据范围 |
|---|---|---|
| [SkVM](https://arxiv.org/html/2604.03088v3) | capability 编译、环境绑定、运行时模式固化与回退 | 本项目基座；已有 JIT 和固化概念。论文中的加速结果属于上游实验，不能记为本分支成果 |
| [Trace-based JIT Type Specialization, PLDI 2009](https://www.cs.williams.edu/~freund/cs434-exemplar/gal-trace.pdf)；[CPython JIT](https://github.com/python/cpython/blob/main/InternalDocs/jit.md) | 热路径、守卫、失败出口、恢复活跃值 | 启发“带状态退出”。Agent 工作区、外部动作和语义质量没有解释器那样完整的形式语义，需要显式定义可恢复边界 |
| [LLMCompiler](https://arxiv.org/html/2312.04511v3) | 按数据依赖组织工具 DAG、替换前序输出、调度并行任务 | 说明工具依赖应显式化；规划并行与跨运行固化是不同优化，评测要分别计量 |
| [SkillSmith](https://arxiv.org/html/2605.15215v1) | 按源结构区分 workflow/dispatcher/reference 等，编译操作边界、验证和 fallback | 与“分类＋边界编译”直接重叠。其 execute/guidance/blocked 及原 skill 恢复值得复用；恢复原包内容与恢复任意中途执行状态要分别验证。公开评测为选定 SkillsBench 任务 |
| [TraceCompiler](https://arxiv.org/html/2608.02680v1) | 区分常量、用户输入、前序输出、转换和残余 LLM；只有来源明确时才建立数据边 | 对依赖恢复很有帮助。原文仍缺完整 WorkflowIR runtime；支付案例依赖手工转写模拟调用，编译成本及环境漂移未充分测量，不能直接当成熟生产方案 |
| [Agent JIT Compilation](https://agent-jit-compilation.github.io/) | 从成功轨迹生成工具、设置前后条件、组合调用及执行调度 | 有界程序候选和执行成本选择可借鉴；本课题仍需说明分类、检查失败和状态接续带来的独立增量 |
| [Adaptive Skill Granularity](https://arxiv.org/html/2610.31461v1) | micro/macro/hybrid 路由，验证驱动的 macro-to-micro 恢复 | 与粒度选择和恢复高度重叠。公开结果是小型 pilot，自动宏生成仍是后续问题；早期失败与已接近完成的晚期失败收益不同，应进入本项目评价 |
| [Nickerson 等，2013 分类方法](https://d-nb.info/1256597325/34) | 以分类用途确定维度，结合概念和观察迭代 | 分类服务优化决策。先做能被复核的多维标注，再检验类别是否有用，不预设一套涵盖所有 skill 的分类树 |

**创新点目前是待验证假设。** 单独“编译 skill”“选择宏/微粒度”“失败回退”已有直接相关工作。可研究的增量是：类别与数据依赖共同选择固化范围和验证方式，失败后只撤回受污染的数据，并在多类真实任务上证明质量保持与摊销收益。若类别没有带来选择改善，应如实保留运行特征路由，不能为题目强加分类优势。

## 4. 分类：任务用途与运行特征分开

分类单元是任务中的候选子流程；skill 层保留多个标签。初始用途类别如下，是研究工作分类，不是现成能力清单。

| 用途类别 | 例子 | 优先尝试的固化/检查 |
|---|---|---|
| 结构化转换与提取 | CSV 清洗、配置变换、接口样例构造 | 字段/行级程序；schema、计数、保存约束、差分测试 |
| 约束产物构建 | 文档、PPT、带模板的报告 | 脚手架与格式操作；可解析性、结构/引用/版式要求；内容判断保留给模型 |
| 规则驱动的工具流程 | 环境检查、明确规则的数据处理与工具组合 | 有界步骤图；输入前置条件、结果契约和效果确认 |
| 语义判断与开放内容 | 授权评估、翻译、选题、内容设计 | 固化检索/统计/渲染等机械部分；核心判断继续由模型完成并独立评价 |

每段再记录运行特征：输入/输出类型、数据来源、控制分支、环境和源码依赖、是否读写外部状态、结果是否可独立检查、失败后的可恢复状态。写服务、发消息、操作数据库是额外的效果属性，不混成一个互斥用途类。

一次真实 trace 能证明该次经过的路径，不能证明其他分支都稳定。重复的命令文本也可能依赖当前时间、网络、目录状态或隐藏文件。来源不能唯一归属的值保留未确定；避免把示例常量误固化成业务规则。

类别提供初始选择倾向，具体能否执行由本次输入、依赖和验证覆盖决定。先用可解释的规则选择，积累数据后再判断是否需要学习型路由器。

## 5. 粒度、验证和恢复三条独立轴

| 粒度 | 接管范围 | 适用前提 |
|---|---|---|
| T0 | 原 agent 流程 | 没有可靠候选，或执行/检查成本不合适 |
| T1 | 单个操作 | 参数来源明确，效果与结果可观察 |
| T2 | 一个有界子流程 | 步骤依赖和出口明确，可把中途状态交回 |
| T3 | 一个完整的有界任务 | 所需分支及最终结果有相应验证依据；其余输入仍回 T0/T1/T2 |

T3 不表示“高质量”，只表示覆盖范围更大。一个 T1 也可能需要严格的外部效果检查。验证分别选择结构约束、保存/完整性约束、差分依据或语义评价，明确各自未覆盖什么。

候选来源顺序：已有 skill 脚本 → 轨迹中可参数化的程序 → 模型生成局部程序。保留模型负责的余下职责，不把整包缩成一个结果文件。运行时不能把编译期已暴露答案当作业务输出模板。

### 状态交还合同（拟议）

检查点放在可解释的步骤边界，记录：本次任务与输入、已完成步骤及验证结果、当前有效变量/文件、失败步骤与诊断、尚未完成职责、效果回执和依赖版本。

成功子流程的工具结果进入普通 trace，agent 继续处理剩余任务；完整任务经最终检查通过才结束。失败时保留已经验证的前缀，撤回失败步骤及依赖它的结果，给模型一份紧凑的当前状态，必要原件通过路径读取。

本地输出可先写暂存区、检查后发布；已发生的外部效果要有回执，完成状态未知时不自动重发。恢复不意味着默认再执行整个前缀。模型接手后的新增调用、耗时和结果检查全部归入这次运行。

需要区分：输入不适用、程序异常、退出成功但结果错误、依赖变化、外部效果未知、恢复后仍失败。只有格式错误的失败与语义错误分别分析，但二者都属于用户实际付出的端到端成本。

## 6. 如何证明有用

主要比较按类别报告，按同一 skill/任务/输入/模型/harness 配对。开发材料与最终测试分开；旧 Download/Memos、旧 CSV 和 I18n 等已暴露输入只能用于开发或历史复验。

| 条件 | 用途 |
|---|---|
| 原 skill＋原 agent | 用户实际基线 |
| 现有 SkVM JIT | 判断是否只是重现已有能力 |
| 同候选/同验证器的固定粒度 | 判断选择粒度的价值 |
| 类别＋运行特征的选择策略 | 新方法的整体效果 |
| 去类别、保留运行特征；失败全重做对比状态接续 | 分别检验分类和恢复的贡献；在离线可控场景进行 |

先做两个或三个结构明显不同的类别，每类多个独立 skill 和变化任务；规模在小型接线通过后确定。样本选择依据任务结构，不能只选已经优化成功的 skill。准确标明真实来源、用户任务、合成边界输入及人为故障。

质量评价先登记各任务必需条件和语义量表；预先确定非劣界限，报告差值和不确定性。小样本先报告逐项结果，不用“无显著差异”证明质量不降。正确结果、未交付、合理拒绝和错误分开列出，拒绝不能计为任务成功。

运行指标包括端到端 wall time、真正派发的模型调用数、完整 input/output/cache、工具执行和检查时间、恢复次数及成功率。provider 的 cache 字段按定义计一次；节省调用必须计入分类、参数提取、模型检查与恢复的调用。USD 未报告时保持未知。

编译/作者/本地验证成本单列，并给出首次使用和多次复用的摊销结果：`总成本 = 编写与验证成本 + 各次运行成本`。token、时间、费用分别算，不能随意相加。失败运行进入总量；成功配对的加速比作为附表，不替代全队列统计。

正向主张应是“在某类任务、某输入范围内，通过所列质量评价，延迟或调用量改善多少”。某项更快但质量下降，或恢复频繁导致总成本增加，应记录取舍/负结果，不继续靠扩预算掩盖。

## 7. 现有结果如何继承

- U 阶段四组成对任务 checker 均为 4/4；耗时下降 56.79%，输出 token 下降 75.66%，但总 observed token 上升 60.59%。它证明有可用局部路径，也说明不能只看输出 token。见 [U effect report](../../results/skill-ir/trace-guided-skill-optimization-20260913/u6/effect-report-all.json)。
- G 阶段覆盖四个 skill、九次自然消费，八次独立评价中五次通过；严格 I18n 配对的 input 降低，但整体仍 mixed。见 [G final report](../../results/skill-ir/general-skill-optimization-20260913/final-report.json)。
- BU 的 Memos 有限源码差分让匹配项从 14/30 变为 23/30，反例及未知下降；这是局部检验与修稿价值。它没有证明新课题的跨类质量、状态恢复或运行时净节省。见 [BU summary](../../results/skill-ir/skill-dsl-research/development/authorization-source-differential-v1/summary.json)。

旧授权 DSL 的自然答案面板不再作为主线反复扩展。保留有限程序、检查器和失败案例；新原型优先补普通运行时的中途接续，而不是继续把 Download 解释得更细。

## 8. 下一阶段与维护方式

第一段开发只实现一种可检查的本地子流程，打通 T1/T2、成功继续、检查失败恢复及完整计量。用 mock 模型和确定性测试证明接线，再用真实账号运行少量原包/优化包配对。候选是否来自自动作者和恢复是否实际减少重做分别留证。

具体文件、失败测试和顺序统一维护在 [plan](skill-ir-aot-optimization-plan.md)。本轮不自动启动实验、不新增生产默认。官方账号实验授权延续，第三方付费调用继续暂停。
